# 03 · 共享记忆机制设计

> 核心诉求：以**功能单位**实现共享，共享的不是完整记忆，而是**结构化、二次/三次整理的内容 + 任务 + 技能**。
> 为提高缓存命中率，**共享部分只增不改不减，修改只追加**，且修改部分追加到最后但权重较高。

---

## 一、设计理念

### 1.1 为什么不是完整记忆

完整记忆（对话历史）有三个致命问题：
1. **冗余噪音**：大量讨论过程、试错、临时状态，检索命中率低；
2. **耦合污染**：完整对话会让不同 agent 读到不相关内容，导致互相干扰；
3. **不可控**：完整记忆难以做权限隔离、版本管理、缓存优化。

因此共享记忆只存**整理过的结构化产物**——即"经过二次、三次整理的内容"：
- **二次整理**：原始协作 → 提炼为结构化条目（机制分析/系统设计/决策记录）
- **三次整理**：二次条目 → 去重/归并/索引 → 形成高价值知识（已验证工作流/技能）

### 1.2 以功能单位为粒度

共享记忆按**功能单位**（游戏系统）组织，而非全局共享：
- 例：`背包系统` 一个空间，`战斗系统` 一个空间，`经济系统` 一个空间……
- 只有负责该系统的 agent 组共享该空间记忆，避免跨功能污染。
- 空间是父子树（根→小组→子小组），可精确到功能子系统。

---

## 二、共享记忆的三类内容

| 类型 | 内容 | 整理层级 | 示例 |
|------|------|---------|------|
| **内容记忆** | 结构化知识/产物/决策 | 二次/三次 | 机制分析、系统设计、支柱裁决、里程碑结论 |
| **任务记忆** | 任务卡/依赖/状态/验收 | 结构化任务 | epic、故事、任务、验收标准、依赖关系 |
| **技能记忆** | 已验证的工作流/playbook | 三次 | 最佳实践、经验教训、复用模板 |

每类记忆都是**结构化**的（JSON/字段化），不是自由文本，便于检索、版本管理、权限控制。

---

## 三、记忆记录结构

```python
@dataclass
class SharedMemoryRecord:
    mem_id: str            # 主键：loc://memory.<space>.<kind>.<seq>
    space: str             # 功能单位空间（如 "backpack_system"）
    kind: str              # content / task / skill
    content: dict          # 结构化内容（JSON）
    owner: str             # 负责 agent
    version: int           # 版本号（追加递增）
    weight: float          # 检索权重（追加的新版本权重更高）
    status: str            # active / superseded（被新版本追加覆盖，但保留）
    created_at: str        # 创建时间
    prev_mem_id: str       # 前驱记录（指向被追加覆盖的旧版本）
```

---

## 四、核心机制：只增不改不减 + 修改只追加

### 4.1 不变性（Immutable）

- **共享部分一旦写入不可删除、不可修改**（`status` 只标记 `superseded`，物理行保留）。
- 保证：① 缓存命中率高（旧记录恒有效）；② 可回溯；③ 无并发写冲突。

### 4.2 修改只追加（Append-only）

当一条共享记忆需要修订时：

```
原记录:  loc://memory.backpack_system.content.007   version=1  weight=1.0  "容量规则 v1"
修订时:  不修改原记录
        → 新增记录 loc://memory.backpack_system.content.007  version=2  weight=1.5  "容量规则 v2"
        → 原记录 prev 链指向新版本，原记录 status=superseded
```

- **不覆盖、不删除**原记录；
- **新增一条更高 version 的记录**，通过 `prev_mem_id` 形成版本链；
- 检索时默认取**最高版本**（即最新追加），但历史版本仍可回溯。

### 4.3 权重机制（修改追加部分权重更高）

- 每条记忆记录带 `weight`（检索加权值）。
- **追加的新版本权重更高**（如 v2 权重 1.5 > v1 权重 1.0），保证**时效性优先**。
- 检索排序：`relevance_score × weight`。
- 效果：**缓存命中率高**（旧记录不失效），**最新修订优先**（新版本权重高），二者兼顾。

### 4.4 只增不改不减 vs 缓存命中率

```
传统可变记忆（改）：  缓存经常失效，需重算/重取 → 命中率低
本设计追加式（只增）：旧记录恒有效，缓存稳定命中；修订走新版本
                      → 命中率高 + 时效性通过 weight 保证
```

## 五、共享记忆的写入流程（三次整理）

```
协作产出（机制分析/系统设计/决策/经验）
   │  第一次整理（原始结构化）
   ▼
二次整理：提炼为结构化条目（去噪、字段化、归一到 space）
   │  写入 memory 表，kind=content/task
   ▼
三次整理：跨条目去重、归并、提炼通用技能/经验
   │  写入 memory 表，kind=skill
   ▼
索引建立：为每条记忆建立检索索引（空间/类型/关键词/向量）
```

**数据管理员（游戏·数据管理员）统一执行**写入/校验/归档，统一口径，禁止 agent 自造。

---

## 六、检索与触发

### 6.1 检索
- 按 `space` 隔离：只检索当前功能单位空间记忆；
- 按 `kind` 过滤：内容/任务/技能分开取；
- 排序：`relevance × weight`，最新追加优先；
- 支持语义向量检索（复用 memory 引擎）：输入 → 向量化 → 与记忆比对。

### 6.2 与条件触发结合
- 共享记忆里的**技能记忆**可作为触发基准：
  - 某 agent 首次遇到某类任务，从共享技能记忆检索对应 playbook；
  - 语义命中某角色职责域 → 自动触发该角色（复用三层触发机制）。

---

## 七、权限（ACL）与隔离

- 每个功能单位空间可声明 ACL：`r|w|rw|none`。
- 只有该功能小组的 agent 可读写其空间记忆，防止跨功能污染。
- 未授权读写被拒绝（`loc://` 寻址 + ACL 校验）。

---

## 八、落地实现

- 存储：沿用 `collab` 的 `memory` 表 + `spaces` + `acl`，扩展 `version/weight/prev_mem_id/status` 字段。
- 接口：`src/shared_memory.py` 提供统一 CRUD：
  - `add_record(space, kind, content, owner)` → 追加一条
  - `revise(mem_id, new_content)` → **追加新版本**（不覆盖原记录）
  - `query(space, kind, topk)` → 按 `relevance×weight` 检索
  - `get_latest(mem_id)` / `get_history(mem_id)` → 最新版本 / 全版本链
- 后端：SQLite 默认零依赖；生产切 PostgreSQL。

## 九、示例（背包系统共享记忆）

```
space=backpack_system
┌─ content ─────────────────────────────────────────┐
│ .001 v1 w1.0  容量=20格，堆叠上限=99（初始设计）    │
│ .001 v2 w1.5  容量=20格，堆叠上限=99→999（改版追加）│ ← 最新，权重高
│ .002 v1 w1.0  存取规则=按类型分区（v1）             │
│ .003 v1 w1.0  决策:背包不加入付费扩展(支柱裁决)      │
└───────────────────────────────────────────────────┘
┌─ task ────────────────────────────────────────────┐
│ .T1 v1  任务:实现背包UI(依赖 系统设计)  状态:进行中 │
└───────────────────────────────────────────────────┘
┌─ skill ───────────────────────────────────────────┐
│ .S1 v1  技能:背包系统通用实现playbook(经验沉淀)     │
└───────────────────────────────────────────────────┘
```

检索"背包堆叠上限"时：`.001 v2` 因 weight 1.5 优先命中，同时可回溯 v1 原始设计。

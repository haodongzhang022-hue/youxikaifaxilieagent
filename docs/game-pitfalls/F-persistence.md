# F 数据与持久化坑点

> 危害等级：🟠 游戏服务进程重启即丢数据，等于玩家所有进度、货币一夜归零。这是比刷钱
> 更直接的毁灭性事故。**关键账本与进度必须落盘/持久化。**

---

## <a name="F1"></a>F1 关键数据只在内存（重启即丢）

- **现象**：`EconomyService._ledger`、`WorldState._world_state`、`CombatService._sessions`
  全部为**进程内存态**，无落盘、无持久化。进程重启/崩溃即清零。
- **危害**：玩家进度/货币回档；被刷后也无法回滚恢复。
- **修复**：账本与玩家数据持久化到 DB / 定期快照 / WAL。
- **本仓现状**：⚠️ 全部内存态，仅限原型演示；生产必须持久化。

---

## F2 无回滚/备份能力

- **现象**：发现被刷后无法回滚到事发前账本。
- **危害**：经济已崩且无法恢复。
- **修复**：账本定时快照 + 增量日志，可回滚到任意时间点。
- **本仓现状**：⚠️ 无。

---

## F3 交易流水无持久化

- **现象**：`_transactions` 只存内存，无法审计历史。
- **修复**：流水落 DB。
- **本仓现状**：⚠️ 内存态。

---

## F4 写入非原子（断电半写）

- **现象**：落盘/写库非事务，断电导致半写损坏。
- **修复**：DB 事务 + 冗余校验。
- **本仓现状**：✅ 无持久化，暂不涉及；引入持久化时须事务化。

# A 经济与货币坑点

> 危害等级：🔴 经济是网游的生命线，刷钱/负数转账可直接让经济体系崩盘、排名失真、
> 平台追责。**涉及金钱与账本的每一行都必须先校验，再入账。**

---

## <a name="A1"></a>A1 负数/零金额转账（货币复制/倒刷）

- **现象**：`credit/debit/transfer` 未校验 `amount <= 0`。负数入账 = 直接反向加钱；
  借 debit 负数 = 余额反而增加（因为 `balance < amount` 负数恒不成立）。
- **危害**：任意玩家传 `amount=-1e9` 即可无限刷钱；或 transfer 负数反向入账。
- **复现**：`transfer(from, to, "gold", -1000000)` → to 被扣款、from 反而增加（若校验缺失）。
- **检测**：搜所有 `credit/debit/transfer` 调用点，确认入参前有 `amount > 0` 校验。
- **修复**：统一在 `credit/debit/transfer` 入口加 `if amount <= 0: return error`。
- **本仓现状**：✅ **已命中 C1**。`EconomyService.credit/debit/transfer` 均未校验
  `amount <= 0`，`debit` 用 `balance < amount` 判断，负数恒通过。**必须修复。**

---

## A2 浮点数记账 / 金额误差

- **现象**：用 `float/double` 存货币，累加/扣减产生精度误差（0.1+0.2≠0.3）。
- **危害**：长期交易对不上账，运营查账无解。
- **修复**：货币一律用**整数（最小单位，如 分/钻石/铜币）**或定点数；禁止浮点记账。
- **本仓现状**：✅ 本仓货币用 `int`，符合要求。

---

## <a name="A3"></a>A3 转账无来源/无上限校验（资金漂移/洗钱）

- **现象**：`transfer` 允许任意 from→to 且金额无上限；或 to 是目标自己（自我转账
  循环）。网关虽校验了 session，但服务层 `transfer` 本身可被内部误调/绕过调用。
- **危害**：配合其他漏洞可大规模转移黑金、制造资金漂移痕迹。
- **检测**：确认 `transfer` 内 from 是调用者本人、to ≠ from、金额有上限与频率限制。
- **修复**：`transfer` 内校验 `from == 当前会话 player`；拒绝 `to == from`；加单笔上限、
  频率限流、全量审计。
- **本仓现状**：⚠️ 网关已挡 from，但服务层 `transfer` 自身无 `to==from`、无上限、无限流。

---

## A4 缺少幂等/防重放（重复入账）

- **现象**：同一笔奖励因客户端重发/断线重连被结算多次，重复入账。
- **危害**：奖励、充值、战斗奖励被无限重复领取。
- **修复**：账本操作带业务幂等键（combat_id/order_id），已处理过的键直接返回原结果。
- **本仓现状**：⚠️ 战斗胜利发奖无幂等键，客户端可重发 `attack` 重复领奖（若会话未清）。

---

## A5 只记余额不记流水（无法对账）

- **现象**：只更新 `balance`，不落交易流水，出问题无法回溯。
- **危害**：被刷后查不出钱从哪来、流向哪。
- **修复**：每一笔都写 `{player, currency, delta, balance, reason, ts}` 全审计流水。
- **本仓现状**：✅ 已有 `_transactions` 全审计流水，良好。

---

## A6 初始资产/奖励配置错误（通胀源头）

- **现象**：初始赠送或掉落配置数值失控（如掉落数量未乘权重/概率错），导致产出>消耗。
- **危害**：全局通胀。
- **修复**：掉落/赠送统一走配置表 + 数值策划复审。
- **本仓现状**：⚠️ 战斗奖励固定 `50 + seed%50` XP、掉落数量与中间件不一致（见 C1），
  数值需与配置统一。

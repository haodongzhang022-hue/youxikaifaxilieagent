# G 数值与边界坑点

> 危害等级：🟡 数值溢出/除零/极值看似低级，却是玩家可以稳定触发的"核弹"，一旦被刷即崩服。

---

## <a name="G1"></a>G1 整数溢出

- **现象**：`amount`/`damage`/`xp` 无上限，超大值累加溢出（int 溢出为负）。
- **危害**：溢出为负 → 反向入账/扣负；伤害溢出秒杀。
- **检测**：所有 `amount` 输入校验上限；累计值用大整数/防溢出。
- **本仓现状**：⚠️ `process_attack` 的 attack_power 无上限（见 E1）；`collect amount` 无上限。

---

## G2 除零 / 除极小值

- **现象**：伤害公式中 `def` 为 0 或极小 → 除零崩溃或伤害爆炸。
- **修复**：除数下限保护 `max(def, 1)`。
- **本仓现状**：✅ `calc_damage` 中 `max(1, ...)` 有保护；`fp_div` 有 `b==0` 保护，✅。

---

## G3 极值/负数坐标、越界索引

- **现象**：客户端传超大/负坐标或负数量，未校验导致数组越界/异常。
- **修复**：所有数值入参做上下限白名单。
- **本仓现状**：⚠️ 坐标有 `abs<=10000` ✅，但 `amount`/`attack_power` 无上限（见 G1/E1）。

---

## G4 状态机非法跳转

- **现象**：战斗/玩法状态可被客户端任意跳转（未开始就 victory / 已结束再 attack）。
- **修复**：状态机强校验合法转移。
- **本仓现状**：⚠️ `process_attack` 对 `finished` 有拦截 ✅，但未校验会话是否"该玩家所有"（B1）。

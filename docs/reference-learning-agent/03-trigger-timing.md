# 03. 触发时机（Trigger Timing）

定义 Agent 在什么场景、由谁、以何种方式被唤醒。触发分为 **主动（Proactive）** 与 **被动（Reactive）** 两类。

## 1. 触发分类总览

| 类型 | 触发源 | 说明 | 优先级 |
|------|--------|------|--------|
| 指令触发 | 用户/玩家 显式指令 | 直接要求"借鉴某游戏的某机制" | 高 |
| 事件触发 | 竞品/市场事件 | 竞品发布新玩法、热门玩法爆火 | 中 |
| 数据触发 | 自有游戏运营数据 | 留存/流失异常，主动对标行业最佳实践 | 中 |
| 定期触发 | 定时任务 | 周期性"玩法雷达"扫描 | 低 |
| 回流触发 | 需求队列 | 前次被搁置/排队待处理的借鉴点重新调度 | 中 |

## 2. 触发条件细化

### 2.1 指令触发（Reactive · 最高优先级）
- 触发信号：用户显式提出，如 *"参考《X》的建造循环"*、*"把《Y》的悬赏系统做进来"*。
- 唤醒后动作：进入 `INPUT_PENDING`，归一化素材后开始分析。

### 2.2 事件触发（Reactive）
- 触发信号：检测到竞品上新玩法 / 热门玩法话题突增 / 用户社区大量提及某机制。
- 由"市场监控"模块生成一条**借鉴候选**，进入队列，但不抢占正在进行的任务。

### 2.3 数据触发（Reactive）
- 触发信号：自有游戏运营指标出现异常（如新玩家流失率 > 阈值）。
- 动作：针对异常环节，检索知识库中"已被验证可改善该环节"的借鉴，生成优化 Mod 提案。

### 2.4 定期触发（Proactive）
- 触发信号：定时任务（如每周玩法雷达）。
- 动作：扫描近期热门/同品类游戏，输出《玩法雷达周报》，仅作推荐不自动落地。

### 2.5 回流触发（Reactive）
- 触发信号：队列中被延迟的借鉴点重新满足执行条件（人力/资源就绪）。
- 动作：按优先级调度继续执行。

## 3. 触发准入（Gate）机制

并非所有触发都立即进入完整流程。设置**准入门槛**，避免滥用计算资源：

```
触发信号
   │
   ▼
┌───────────────┐
│  GATE 校验     │  ① 是否已有相同/相似借鉴（查知识库）？
│  - 去重        │  ② 目标游戏素材是否充分？
│  - 素材完备    │  ③ 契合度初筛是否通过？
│  - 契合初筛    │
└───────┬───────┘
        │ 通过
        ▼
   进入 ANALYSIS 完整流程
        │ 未通过
        ▼
   归档为"候选/放弃"，写入知识库，不进入落地层
```

- **去重**：知识库命中相似借鉴 → 直接复用或更新，不重复落地。
- **素材完备**：素材不足以支撑理解层 → 先回写"待补充素材"清单，挂起等待。
- **契合初筛**：类型/受众明显不匹配 → 直接给"建议不落地"结论，节省算力。

## 4. 并发与抢占规则

- Agent **串行执行**单一借鉴流程，不并发多路完整落地，保证一致性。
- 高优先级（指令触发）可抢占低优先级（定期触发）的进行中任务：
  - 被抢占任务先落盘当前进度（保存《分析报告》草稿），恢复时续跑。
- 队列上限：借鉴候选队列默认容量 20，超出按优先级/时间淘汰。

## 5. 触发后的上下文注入

每次唤醒时，Agent 自动注入以下上下文，保证行为一致：

| 上下文 | 来源 |
|--------|------|
| 自有游戏基线（主版本、当前 Mod 列表） | 仓库/版本库 |
| 已有借鉴知识（知识库检索结果） | 仓库知识库 |
| 运行策略（能力成熟度 L0-L3 配置） | 策略配置 |
| 用户意图与优先级 | 触发信号携带 |

## 6. 触发结果反馈

- 每次触发结束，统一产出一条结构化结果（决策单 + Mod），并同步：
  - 回写知识库（供后续检索）；
  - 在 Issue/讨论区输出摘要，供人工审阅。

# 游戏开发岗位体系调研报告

> 目标：梳理当前游戏开发行业的一般工作岗位，按人类分工建立岗位模型，为后续 Agent 化替代提供基础。

## 一、游戏开发全流程岗位全景

游戏开发是一个**多学科交叉的复杂工程**，通常可划分为以下大板块：

```
┌─────────────────────────────────────────────────────────────────┐
│                        游戏开发全景                                │
├──────────┬──────────┬──────────┬──────────┬──────────┬─────────┤
│  策划     │   程序     │   美术     │   测试    │  项目管理  │  运营   │
│  Design   │  Program  │   Art     │   QA      │   PM      │  Ops    │
├──────────┼──────────┼──────────┼──────────┼──────────┼─────────┤
│ 玩法/系统 │ 客户端    │  原画     │  功能测试  │  版本管理  │  数据分析 │
│ 数值      │ 服务端    │  3D建模   │  性能测试  │  进度管理  │  用户运营 │
│ 剧情      │ 引擎      │  特效     │  兼容性    │  风险管理  │  活动策划 │
│ 关卡      │ 工具链    │  UI/UX   │  自动化    │  需求管理  │  客服     │
│ 音频      │ 测试工具  │  动画     │  安全      │  流程管理  │  发行     │
└──────────┴──────────┴──────────┴──────────┴──────────┴─────────┘
```

## 二、岗位详细定义

| 岗位 | 别名 | 职责 | 核心产出物 |
|------|------|------|-----------|

| 系统策划 | System Designer | 游戏系统设计（背包/商城/任务/成就等） | 系统设计文档 |
| 数值策划 | Balance Designer | 数值模型、经济系统、成长曲线、平衡性 | 数值表/平衡模型 |
| 关卡策划 | Level Designer | 关卡设计、地图布局、难度曲线 | 关卡设计文档/白盒 |

## 三、核心岗位的详细职责与工作流程

以**最核心、最需要 Agent 化的 8 个岗位**做深度拆解：

### 1. 制作人（Producer）

**职责**：整体方向把控、资源决策、里程碑验收、跨团队协调。

**工作流程**：
```
立项 → 定目标(愿景/预算/时间) → 里程碑规划 → 团队组建
→ 每周进度评审 → 风险处置 → 里程碑验收 → 迭代下一阶段
```

**日常任务**：
- 审核策划提案是否符合游戏愿景
- 分配/调整资源
- 决策"做/不做/延期"
- 对外汇报进度与风险

### 2. 主策划（Lead Designer）

**职责**：玩法方向、系统架构、设计文档质量、策划团队管理。

**工作流程**：
```
接收需求 → 玩法构思 → 系统架构设计 → 编写GDD → 团队评审
→ 拆解任务 → 下发设计 → 审核设计 → 跟进实现 → 验收调优
```

**日常任务**：
- 撰写/审核设计文档
- 定义游戏核心循环(Core Loop)
- 评审各策划模块设计的合理性与一致性
- 决策设计冲突

### 3. 系统策划（System Designer）

**职责**：具体系统设计（背包/任务/商城/成就/好友等）。

**工作流程**：
```
接收系统需求 → 竞品分析 → 系统设计(规则/交互/表现) → 编写详细设计
→ 配置数值表 → 与UI沟通 → 与程序对接 → 验收实现 → 迭代调优
```

**日常任务**：
- 编写系统设计文档（规则、流程、边界、异常）
- 设计UI流程与交互
- 定义数据表结构
- 验收系统功能

### 4. 数值策划（Balance Designer）

**职责**：经济系统、成长曲线、平衡性、付费设计。

**工作流程**：
```
接收设计目标 → 建立数值模型 → 参数设计 → 模拟演算
→ 配置数据表 → 平衡性调整 → 数据分析验证 → 迭代调优
```

**日常任务**：
- 设计经济循环（产出/消耗）
- 数值表配置
- 平衡模拟与验证
- 分析玩家数据反哺调优

### 5. 客户端程序员（Client Dev）

**职责**：客户端功能实现、UI、交互、表现。

**工作流程**：
```
接收需求/设计 → 技术方案设计 → 编码实现 → 自测 → Code Review
→ 联调(美术/策划) → 提测 → 修复Bug → 发布
```

**日常任务**：
- 按设计实现功能
- 技术方案评审
- 编写单元测试
- 处理Bug
- 性能优化

### 6. 服务端程序员（Server Dev）

**职责**：网络通信、游戏逻辑、数据存储、防作弊。

**工作流程**：
```
接收需求 → 协议设计 → 架构设计 → 编码实现 → 自测
→ 接口联调 → 压力测试 → 部署上线 → 监控运维 → 迭代
```

**日常任务**：
- 协议与数据结构设计
- 服务端逻辑开发
- 数据库设计与优化
- 性能/稳定性保障
- 安全防护

### 7. 测试工程师（QA）

**职责**：质量保障、Bug发现、版本验收。

**工作流程**：
```
接收版本 → 需求分析 → 制定测试计划 → 编写用例 → 执行测试
→ 提交Bug → 回归验证 → 质量报告 → 版本放行/打回
```

**日常任务**：
- 编写/维护测试用例
- 功能/性能/兼容性测试
- Bug生命周期管理
- 自动化脚本
- 质量评估报告

### 8. 项目经理（PM）

**职责**：计划、进度、风险、协作。

**工作流程**：
```
立项 → WBS拆解 → 排期 → 分配任务 → 每日站会 → 进度跟踪
→ 风险识别 → 资源协调 → 里程碑评审 → 周报 → 复盘
```

**日常任务**：
- 制定/更新项目计划
- 每日跟进进度与阻塞
- 风险管理
- 协调跨团队资源
- 汇报

## 五、Agent化改造要点总结

| 维度 | 人类分工特点 | Agent化改造方向 |
|------|-------------|----------------|
| 岗位职责 | 主观经验驱动 | 知识库+规则+LLM推理 |
| 任务执行 | 串行人工操作 | 自动化+Agent协作 |
| 协作方式 | 会议/IM口头沟通 | 结构化消息+状态机 |
| 知识传递 | 文档+口口相传 | 文档+知识库+上下文记忆 |
| 决策依据 | 经验直觉 | 数据+规则+约束条件 |
| 质量保障 | 人工Review | 自动化检查+Agent互评 |

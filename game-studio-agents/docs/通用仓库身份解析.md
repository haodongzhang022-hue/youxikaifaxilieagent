# 通用仓库身份解析模块（Agent Identity Resolver）

> 面向所有 Agent 的自适应 @ 提及机制：**不写死仓库/组织名**，
> 同仓库不重复适配，跨仓库按「工作仓库」动态重定向到有权限的角色。
> 供 CodeBuddy / 代码审查员 / 游戏向经理 / 合并确认员等所有角色跨仓库协作复用。

## 一、解决的问题

仓库里的 NPC 可能在**其它仓库**被跨仓库召唤。旧写法把召唤目标写死成
`@dongdongxiaozu/youxikaifaxilieagent(CodeBuddy)`（本仓库路径 + 角色名）。

但当本仓库 NPC 被**外部仓库**触发、需要在那个仓库推送/合并/关闭时：
- 写死的身份是本仓库的 CodeBuddy，它在目标仓库**没有写权限**；
- 只有**目标仓库自己**绑定的 CodeBuddy 才具备那里的 push/merge/close 权限。

于是跨仓库协作时权限就成了受限的瓶颈。本模块通用化解决这个问题。

## 二、核心逻辑

1. **识别当前仓库**（本 NPC 注册所在仓库）：优先 `CNB_NPC_SLUG`，
   兜底 `CNB_ROOT_SLUG`/`CNB_REPO_NAME` 组合，再兜底 git remote。
2. **识别工作仓库**（本次被触发时真正在改的 PR/Issue 所在仓库）：
   从 `CNB_EVENT_URL` 解析出 `owner/repo`。
3. **判定同仓库 / 跨仓库**：
   - 同仓库（当前仓库 == 工作仓库）：无需适配，直接用当前仓库角色；
   - 跨仓库（当前仓库 ≠ 工作仓库）：必须把 @ 提及**动态指向工作仓库**的对应角色，
     因为只有工作仓库绑定的角色才具备那里的推送/合并/关闭权限。
4. **产出自适应 @ 提及**：`@<工作仓库slug>(角色名)`，角色名可参数化。

## 三、用法

### 运行期确认应使用的 @ 提及

```bash
# 输出应使用的 CodeBuddy 完整召唤格式（跨仓库自动指向工作仓库）
python3 game-studio-agents/config/agent_identity_resolver.py --mention CodeBuddy

# 输出应使用的「代码审查员」召唤格式
python3 game-studio-agents/config/agent_identity_resolver.py --mention 代码审查员

# 判断当前是否跨仓库触发
python3 game-studio-agents/config/agent_identity_resolver.py --cross-repo
```

### Python 代码内调用

```python
from agent_identity_resolver import resolve_identity, codebuddy_mention

# 完整身份信息
ident = resolve_identity("CodeBuddy")
print(ident.is_cross_repo)   # 是否跨仓库
print(ident.mention_slug)    # 应 @ 的仓库 slug
print(ident.mention)         # @<仓库>(角色名)

# 快捷获取 CodeBuddy 召唤格式
print(codebuddy_mention())
```

### 自测

```bash

```

## 四、规则

| 场景 | 应 @ 的目标 | 说明 |
|------|------------|------|
| 同仓库触发 | 当前仓库的角色 | 无需跨仓库适配 |
| 跨仓库触发 | **工作仓库**的角色 | 只有它具备那里的推送/合并/关闭权限 |
| 角色可参数化 | CodeBuddy / 代码审查员 / 游戏向经理… | 所有角色通用 |

## 五、关键文件

| 文件 | 说明 |
|------|------|
| `config/agent_identity_resolver.py` | 通用身份解析模块（核心） |
| `tests/test_agent_identity_resolver.sh` | 测试信号灯 |
| `.cnb.yml` | 各 NPC 提示引用本模块做自适应定位 |
| `.cnb/settings.yml` | CodeBuddy 角色提示引用本模块 |

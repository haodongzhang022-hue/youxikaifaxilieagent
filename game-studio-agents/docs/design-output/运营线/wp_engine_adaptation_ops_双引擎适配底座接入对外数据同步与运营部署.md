- **模块**：ops / 对外数据同步与运营部署

## 一、背景与同步目标

PR #87（feat: 双引擎适配底座接入 Agent 流水线，`wp_engine_adaptation_integration`）已合入 main。
测试线 `wp_engine_adaptation_qa` 验收回归通过（17/17 断言全绿），
项目管理 `wp_engine_adaptation_pm` 双引擎适配底座项目管理架构里程碑验收通过（GO），
发版门禁 **GO ✅**。

运营线作为流水线末位部门，负责将「双引擎适配底座」这一能力变更做**对外数据同步与运营部署**：
- 让外部协作方/数据方正确理解双引擎适配底座接入后的对外数据口径；
- 让运营侧为后续真实引擎接入（Cocos/UE5 双引擎）提前布局部署与沟通策略。

> 双引擎适配底座（engine_adapters / engine_sync / deepseek_harness）为内部技术底座，
> 当前 Mock 模式预留基础设施，真实引擎接入需真机环境验证（Windows + Cocos/UE5）。
> 本工作包聚焦「对外同步 + 运营部署」的机制闭环，不以真机运行为前置。

## 二、对外数据同步要点（data_analyst · wp_engine_adaptation_ops__sub1）

### 2.1 双引擎适配底座接入对外数据口径

| 数据维度 | 适配前 | 适配后（对外口径） |
|---------|--------|-------------------|
| 引擎资源格式 | 单引擎硬编码 | `_engine_resource_hint` 统一资源格式映射（cocos→.mp3/.png/.ts，unreal→.wav/.png/.uasset） |
| 引擎能力差异 | 无统一适配 | engine_adapters 统一接口 + `get_engine` 能力差异适配 |
| 引擎同源校验 | 无 | engine_sync `verify_manifest` 双引擎一致性报告 |
| 引擎上下文 | 无统一口径 | `_engine_resource_hint(engine_ctx, resource_type)` 标准化引擎上下文 |

### 2.2 对外数据埋点建议

- **引擎资源格式埋点**：将 `_engine_resource_hint` 的资源格式映射接入数据埋点通道，
  记录引擎类型、资源类型、格式命中率，为运营决策提供引擎资源洞察；
- **引擎一致性统计**：消费 engine_sync `consistency_report` 上报的双引擎一致性指标，
  为运营侧评估双引擎协同效率提供数据支撑；
- **对外数据同步**：对外方（渠道/数据平台）可订阅引擎事件主题，
  无需感知内部引擎适配实现细节。

### 2.3 运营数据对接说明

| 对接方 | 对接数据 | 方式 |
|-------|---------|------|
| 数据平台 | 引擎资源格式/一致性统计 | 订阅引擎事件主题 + `_engine_resource_hint` 上报 |
| 运营看板 | 双引擎适配状态/一致性报告 | `consistency_report` 上报 |
| 渠道合作方 | 引擎适配接入进度 | 对外发版口径（Mock → 真机） |

## 三、对外部署与沟通策略（game_operator · wp_engine_adaptation_ops__sub2）

### 3.1 对外沟通对象与同步内容

| 沟通对象 | 同步内容 | 优先级 |
|---------|---------|-------|
| 发行/渠道合作方 | 双引擎适配底座接入进度、Mock 模式预留基础设施、真实引擎接入规划 | P0 |
| 玩家/社区 | 双引擎适配为内部技术底座，不直接影响用户可见功能，无需用户侧同步 | P2 |
| 内部团队 | 双引擎适配底座接入流水线、对外数据口径、真机接入依赖 | P0 |

### 3.2 运营部署节奏

| 阶段 | 内容 | 触发条件 |
|------|------|---------|
| D1 Mock 预留 | 对外说明双引擎适配为预留基础设施 | PR #87 合入后 |
| D2 真机接入 | Windows + Cocos/UE5 真机环境联调 | 真机环境就绪 |
| D3 全量部署 | 双引擎适配能力全量对外开放 | 真机联调通过 + 发版门禁 GO |

### 3.3 对外沟通话术要点

- 双引擎适配底座为**预留基础设施**，当前 Mock 模式完成架构闭环，不改变用户可见体验；
- 真实引擎接入需 Windows + Cocos/UE5 环境，属后续程序线真机验证范围；
- 对外数据同步以引擎事件订阅为准，无需对外方感知内部适配实现细节。

## 四、对外部署影响调研与借鉴（reference_learner · wp_engine_adaptation_ops__sub3）

### 4.1 双引擎适配底座接入对运营部署的影响范围

| 影响面 | 说明 | 运营应对 |
|-------|------|---------|
| 引擎资源格式差异 | Cocos 使用 .mp3/.png/.ts，UE5 使用 .wav/.png/.uasset | 运营分层沟通，避免对外口径混淆 |
| 双引擎一致性 | engine_sync 提供同源校验，双引擎产出一致性有保障 | 运营可同步「双引擎一致」对外口径 |
| 能力差异适配 | Cocos 27 能力无 Blueprint、UE5 含 Blueprint | 运营按目标平台规划发布节奏 |
| 真机接入依赖 | Windows + Cocos/UE5 真机环境 | 运营侧准备真机接入对外说明预案 |

### 4.2 借鉴与部署建议

- **借鉴成熟做法**：参考双引擎适配层（engine_adapters）的「统一入口 + 能力差异适配」模式，
  运营部署时以「对外统一口径 + 内部分层适配」为原则；
- **部署落地建议**：将双引擎适配底座接入对外同步纳入发版检查单，真机接入前完成对外数据口径对齐；
- **风险预案**：Mock → 真机切换期间，运营侧需准备对外说明以应对渠道/数据方查询。

## 一、评审职责边界要点梳理

### 1. 评审只读边界（Review Read-Only Boundary）

**评审角色（代码审查员）全链路零推送动作**：

| 能力项 | 边界说明 |
|--------|---------|
| 职责范围 | 读代码 + 给意见，**不包含** push / merge / close 操作 |
| 发现问题处理 | 评论末尾召唤 `@<slug>(仓库处理专员)` 或 `@<slug>(CodeBuddy)` 承接修复 |
| 修复执行者 | 仓库处理专员（本仓库唯一执行者）→ CodeBuddy（通用兜底） |
| 禁止动作 | 评审不得自行修改代码、不得推送、不得打标签 |

### 2. 打标签驱动闭环（Tag-Driven Loop）

本系统**故意设计不允许 push**，闭环通过**打标签**驱动：

| 标签 | 语义 | 触发 |
|------|------|------|
| 「适合推送」 | 修复完成 | 仓库处理专员修复后打此标签 → 触发新一轮评审 |
| 「适合合并」 | 评审通过 | 评审通过后打此标签 → 进入合并门禁 |
| 「适合关闭」 | 无法解决 | 无法就地解决时打此标签 → 标记关闭 |

**只有仓库处理专员**是打标签唯一执行者。

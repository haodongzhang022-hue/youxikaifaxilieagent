## 一、背景与同步目标

PR #89 修复引擎桥接层集成 P1 缺陷（`EngineEventBridge.emit()` 双重投递 + `EngineIntegrationFacade.execute()` 异常路径 TypeError），
程序线 `wp_engine_bridge_verify` 生产就绪验证通过，确认引擎桥接层已满足 Windows + Cocos/UE5 真机接入前置标准；
项目管理 `wp_engine_release` 发版门禁复验签核 **GO ✅**。

据此，`wp_engine_ops`（引擎桥接层接入对外数据同步与运营部署）由 **D1 Mock 预留** 阶段
推进到 **D2 真机接入** 阶段：基于生产就绪的引擎桥接层，推进 Windows + Cocos/UE5 真机接入对外部署。

运营线作为流水线末位部门，负责将「引擎桥接层真机接入」这一能力落地做**对外数据同步与运营部署**：
- 让外部协作方/数据方正确理解真机接入后的对外数据口径（生产就绪后的数据侧落地）；
- 让运营侧为真实引擎接入（Windows + Cocos/UE5）落地部署与沟通策略；
- 让借鉴侧为真机接入对外部署的影响范围与风险预案做调研与借鉴。

> D1（Mock 预留）已在 PR #80 完成，本工作包聚焦 D2（真机接入）的对外同步与运营部署落地，
> 以生产就绪验证通过 + 发版门禁 GO 为前置。

## 二、对外数据同步要点（data_analyst · wp_engine_ops_d2_pr89__sub1）

### 2.1 真机接入后的对外数据口径

| 数据维度 | Mock 阶段 | 真机接入（生产就绪）对外口径 |
|---------|----------|------------------------------|
| 引擎事件 | 预留基础设施 | `EngineEventBridge.emit()` 单次投递修复后，事件稳定可订阅 |
| 引擎命令 | 命令投递 | `execute()` 异常路径带 command 返回，真机连接失败可可靠上报 |
| 能力清单 | Cocos 27 / UE5 32 | 生产就绪双引擎能力集，可对外同步 |
| 引擎事件映射 | 预留 | 引擎事件 → MessageBus 映射正确，对外方可直接订阅 |

### 2.2 真机接入数据埋点落地

- **事件单次投递埋点**：真机接入后，`emit()` 单次投递修复保证每个订阅方恰好收到一次，
  数据埋点计数准确，可真实反映引擎事件量；
- **异常路径埋点**：`execute()` 异常路径携带 command 返回，真机连接失败可可靠记录
  （引擎类型 + 命令 + 失败原因），供运营侧故障洞察；
- **对外数据同步**：对外方（渠道/数据平台）订阅 `ENGINE_EVENT` 主题，消费生产就绪的引擎事件流。

### 2.3 运营数据对接说明（真机接入）

| 对接方 | 对接数据 | 方式 |
|-------|---------|------|
| 数据平台 | 引擎事件单次投递统计 | 订阅 ENGINE_EVENT 主题（emit 修复后计数准确） |
| 运营看板 | 真机接入失败/命令异常 | execute 异常路径 command 上报 |
| 渠道合作方 | 真机接入进度与状态 | 对外发版口径（真机接入 → 全量） |

## 四、真机接入对外部署影响调研与借鉴（reference_learner · wp_engine_ops_d2_pr89__sub3）

### 4.1 真机接入对运营部署的影响范围

| 影响面 | 说明 | 运营应对 |
|-------|------|---------|
| 引擎能力差异 | Cocos 27 能力无 Blueprint、UE5 含 Blueprint | 运营分层沟通，避免对外口径混淆 |
| 平台适配 | 双引擎（Cocos/UE5）真机适配 | 运营按目标平台规划真机接入节奏 |
| 事件投递可靠性 | emit 单次投递修复后事件流准确 | 运营可利用准确事件数据做用户行为洞察 |
| 异常路径健壮性 | execute 异常路径带 command 返回 | 运营可依据故障数据做对外说明与预案 |

### 4.2 借鉴与真机部署建议

- **借鉴成熟做法**：参考双引擎适配层（engine_adapters）「统一入口 + 能力差异适配」模式，
  真机部署时以「对外统一口径 + 内部分层适配」为原则；
- **真机部署落地建议**：将引擎桥接层真机接入纳入发版检查单，真机联调通过后完成对外数据口径对齐；
- **风险预案**：真机连接失败（execute 异常路径）期间，运营侧依据 command 上报数据
  准备对外说明，应对渠道/数据方查询。

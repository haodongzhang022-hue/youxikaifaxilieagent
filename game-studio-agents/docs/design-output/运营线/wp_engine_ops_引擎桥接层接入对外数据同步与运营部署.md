# wp_engine_ops · 引擎桥接层接入对外数据同步与运营部署

- **工作包**：wp_engine_ops 引擎桥接层接入对外数据同步与运营部署
- **部门**：运营线（统一头 · 运营线）
- **触发源**：PR #80（引擎桥接层架构）合并后下游解锁，项目管理 `wp_engine_release` 发版门禁 GO 后级联解锁
- **模块**：ops / 对外数据同步与运营部署
- **依赖**：wp_engine_release ✅、wp_engine_testing ✅、wp_engine_bridge_integration ✅
- **产出物类型**：ops_report（对外数据同步 + 运营部署说明）
- **组内分工**：data_analyst（数据侧）+ game_operator（对外/用户侧）+ reference_learner（技术/借鉴侧）

## 一、背景与同步目标

PR #80（引擎桥接层架构：EngineBridgeFacade + MCP/插件控制 Cocos/UE5）已合并，
程序线 `wp_engine_bridge_integration` 已将引擎桥接层接入 Agent 流水线
（EngineIntegrationFacade + EngineEvent → MessageBus 事件映射）。
测试线 `wp_engine_testing` 与项目管理 `wp_engine_release` 验收通过，发版门禁 **GO ✅**。

运营线作为流水线末位部门，负责将「引擎桥接层接入」这一能力变更做**对外数据同步与运营部署**：
- 让外部协作方/数据方正确理解引擎桥接层接入后的对外数据口径；
- 让运营侧为后续真实引擎接入（Windows + Cocos/UE5）提前布局部署与沟通策略。

> 引擎桥接层当前为 **Mock 模式预留基础设施**，真实引擎接入需真机环境验证（Windows + Cocos/UE5），
> 本工作包聚焦「对外同步 + 运营部署」的机制闭环，不以真机运行为前置。

## 二、对外数据同步要点（data_analyst · wp_engine_ops__sub1）

### 2.1 引擎桥接层接入对外数据口径

| 数据维度 | 接入前 | 接入后（对外口径） |
|---------|--------|-------------------|
| 引擎能力数据 | 无统一出口 | EngineEvent → MessageBus（ENGINE_EVENT）统一投递 |
| 引擎命令数据 | 无埋点 | 命令执行结果 notify_command 发布到 topic=engine_command |
| 引擎事件数据 | 无订阅 | 支持按 event_type 订阅（scene_changed 等） |
| 能力清单 | 未沉淀 | Cocos 27 能力（无 Blueprint）、UE5 含 Blueprint |

### 2.2 对外数据埋点建议

- **引擎事件埋点**：将 `ENGINE_EVENT` 消息接入现有数据埋点通道，记录事件类型、引擎标识、时间戳；
- **能力利用率**：统计 engine_capability_check 上报的能力命中率，为运营决策提供引擎能力洞察；
- **对外数据同步**：对外方（渠道/数据平台）可订阅 `ENGINE_EVENT` 主题，无需感知内部引擎实现细节。

### 2.3 运营数据对接说明

| 对接方 | 对接数据 | 方式 |
|-------|---------|------|
| 数据平台 | 引擎事件/命令统计 | 订阅 ENGINE_EVENT 主题 |
| 运营看板 | 引擎能力/场景加载状态 | engine_capability_check 上报 |
| 渠道合作方 | 引擎接入进度 | 对外发版口径（Mock → 真机） |

## 三、对外部署与沟通策略（game_operator · wp_engine_ops__sub2）

### 3.1 对外沟通对象与同步内容

| 沟通对象 | 同步内容 | 优先级 |
|---------|---------|-------|
| 发行/渠道合作方 | 引擎桥接层接入进度、Mock 模式预留基础设施、真实引擎接入规划 | P0 |
| 玩家/社区 | 引擎桥接为内部技术底座，不直接影响用户可见功能，无需用户侧同步 | P2 |
| 内部团队 | 引擎桥接层接入流水线、对外数据口径、真机接入依赖 | P0 |

### 3.2 运营部署节奏

| 阶段 | 内容 | 触发条件 |
|------|------|---------|
| D1 Mock 预留 | 对外说明引擎桥接为预留基础设施 | PR #80 合并后 |
| D2 真机接入 | Windows + Cocos/UE5 真机环境联调 | 真机环境就绪 |
| D3 全量部署 | 引擎桥接能力全量对外开放 | 真机联调通过 + 发版门禁 GO |

### 3.3 对外沟通话术要点

- 引擎桥接层为**预留基础设施**，当前 Mock 模式完成架构闭环，不改变用户可见体验；
- 真实引擎接入需 Windows + Cocos/UE5 环境，属后续程序线真机验证范围；
- 对外数据同步以 `ENGINE_EVENT` 订阅为准，无需对外方感知内部引擎实现细节。

## 四、对外部署影响调研与借鉴（reference_learner · wp_engine_ops__sub3）

### 4.1 引擎桥接层接入对运营部署的影响范围

| 影响面 | 说明 | 运营应对 |
|-------|------|---------|
| 引擎能力差异 | Cocos 27 能力无 Blueprint、UE5 含 Blueprint | 运营分层沟通，避免对外口径混淆 |
| 平台适配 | 双引擎（Cocos/UE5）适配 | 运营按目标平台规划发布节奏 |
| 事件订阅 | 引擎事件接入 MessageBus | 运营可利用事件数据做用户行为洞察 |

### 4.2 借鉴与部署建议

- **借鉴成熟做法**：参考双引擎适配层（engine_adapters）的「统一入口 + 能力差异适配」模式，
  运营部署时以「对外统一口径 + 内部分层适配」为原则；
- **部署落地建议**：将引擎桥接层接入对外同步纳入发版检查单，真机接入前完成对外数据口径对齐；
- **风险预案**：Mock → 真机切换期间，运营侧需准备对外说明以应对渠道/数据方查询。

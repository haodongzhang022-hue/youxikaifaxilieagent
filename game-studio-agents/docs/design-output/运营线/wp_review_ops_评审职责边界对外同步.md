- **部门**：运营线
- **主责角色**：data_analyst + game_operator（组内 @分工）
- **模块**：ops / 对外沟通
- **依赖**：wp_review_pm ✅（PR 验收通过）、wp_review_qa ✅（PR #75 已合并）

## 一、背景与同步目标

PM `wp_review_pm` 验收通过「评审只读 → 建议 → CodeBuddy/仓库处理专员 修复推送」完整闭环，
确认评审职责边界为**只读 + 给意见 + 打标签标记状态**，无推送/合并/关闭权限。

运营线负责将这一变更**对外同步**，确保外部合作方、渠道、用户社群正确理解：
评审角色不再推送代码，改由仓库处理专员/CodeBuddy 承接修复，闭环经标签驱动。

## 二、评审职责边界对外说明要点

### 2.1 评审只读边界（data_analyst）

| 对外沟通维度 | 说明 |
|-------------|------|
| 评审角色职责 | **只读审查 + 只给意见**，不得推送/合并/关闭代码 |
| 权限边界声明 | 评审仅「读代码 + 给意见」，无 push/merge/close 职责描述 |
| 修复承接 | 需修复时召唤仓库处理专员/CodeBuddy 承接，评审不越权修改 |
| 对运营影响 | 对外沟通时无需期待评审方推送修改，修复统一由仓库处理专员/CodeBuddy 闭环 |

### 2.2 标签驱动闭环（data_analyst）

| 对外沟通维度 | 说明 |
|-------------|------|
| 闭环机制 | 评审→建议→修复→**打标签**（适合推送/适合合并/适合关闭）→触发下一轮评审 |
| 无 push 依赖 | 系统故意设计不允许 push，全程标签驱动，403 卡点归零 |
| 对外影响 | 对外方不需要等待推送事件，以标签状态作为推进信号 |

### 2.3 对外沟通影响（game_operator）

| 对外沟通对象 | 需要同步的信息 |
|-------------|--------------|
| 发行/渠道合作方 | 评审闭环为标签驱动，进度以标签为准，评审不推送代码 |
| 玩家/社区 | 版本节奏不变，评审边界调整不对外公开（内部机制） |
| 内部文档 | README 需更新评审职责描述，明确只读+意见职责边界 |

## 三、外部文档更新建议

## 一、背景与目标

PR #56 落地「评审只读边界」全链路，经测试线 wp_review_qa 回归验证、项目管理线 wp_review_pm 验收确认：
评审 NPC **只读 + 给意见**，无推送/合并/关闭权限，推送闭环统一由本仓库 CodeBuddy 承接。

本工作包目标：**运营线将评审职责边界从内部治理机制转化为对外可理解的说明文档**，
面向社区/用户/外部协作者同步评审边界规则，避免外部协作方对评审角色职责产生误解，
同时确保对外说明与内部治理基线一致。

## 二、对外说明文档内容

### 1. 评审角色职责边界（对外说明）

| 角色 | 职责边界 | 对外说明 |
|------|---------|---------|
| **评审 NPC**（代码审查员） | 只读审查 + 给意见 | 阅读代码/方案、输出审查建议，**不执行**推送/合并/关闭操作 |
| **仓库处理专员** | 修复 + 打标签驱动闭环 | 收到评审意见后执行修复，打「适合推送/适合合并」标签标记状态 |
| **CodeBuddy** | 推送/改动唯一执行者 | 承接评审「需修改」结论，执行代码改动与推送闭环 |

### 2. 评审闭环工作流（对外说明）

```
评审 NPC 只读审查 → 输出意见/建议 → 需修改时召唤 CodeBuddy → CodeBuddy 修复+打标签 → 触发复审
```

### 3. 对外协作方注意事项

- 评审 NPC **不会**直接修改代码/推送变更，其输出仅为**审查意见**
- 如需改动，评审会召唤 CodeBuddy 承接，无需外部协作方重复提交
- 评审不越权处理非本部门职责范围的审查请求

# wp_gameplay_impl · 核心玩法系统实现方案

- **工作包**：wp_gameplay_impl 核心玩法系统实现
- **部门**：程序线
- **主责角色**：client_dev + server_dev
- **模块**：gameplay
- **产出物类型**：tech_doc（技术实现方案）

## 一、客户端实现（client_dev）

**渲染管线**：
- 采用 GPU 驱动渲染管线，场景静态批次合并 + 动态物体合批
- 目标帧率：60fps 稳定（中端机型 45fps 降级保障）
- 资源加载：Addressables 分级加载，首屏 3s 内可交互

**核心循环 UI**：
- HUD 系统：血条/技能栏/任务追踪/小地图，支持自定义布局
- 状态机：规划→行动→反馈→循环，绑定输入与动画状态
- 输入系统：虚拟摇杆 + 技能按键，支持手柄/键盘映射

**数据同步**：
- 本地缓存 + 服务端验证，离线模式支持核心玩法
- 战斗结果本地预测 + 服务端权威校验

## 二、服务端实现（server_dev）

**架构**：
- 采用 Python asyncio 事件驱动架构，支持高并发连接
- 模块化拆分：网关层 / 业务层 / 数据层，层间通过消息队列解耦

**核心系统**：
- 玩家状态服务：角色/装备/资源的持久化与同步
- 战斗验证服务：战斗逻辑权威判定，防作弊
- 任务进度服务：任务/成就进度跟踪与完成判定

**数据层**：
- 分布式缓存（Redis）+ 关系型数据库（PostgreSQL）双写
- 热点数据缓存 TTL 60s，冷数据落盘持久化

## 三、接口契约

```
POST /api/v1/battle/start      启动战斗
POST /api/v1/battle/action     战斗动作上报
POST /api/v1/battle/finish     战斗结算
GET  /api/v1/player/profile    玩家信息
GET  /api/v1/task/list         任务列表
POST /api/v1/task/claim        任务领取
```

## 四、验证指标

- 战斗服务器响应延迟 < 100ms（P95）
- 客户端启动到可交互 < 3s
- 战斗同步带宽 < 50KB/s
- 服务器单实例支持 1000 并发连接

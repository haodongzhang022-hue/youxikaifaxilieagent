## 二、双管线技术栈矩阵（engine_dev · S-2.1）

### 2.1 双管线并存定位

> 对齐架构师「生产矩阵之上叠加发布矩阵」：不推翻既有单向迁移线，而是并存两条对外发布管线。

| 维度 | 管线 A：UE 新路径 | 管线 B：Web→小程序→团结→UE 演进路径 |
|------|------------------|--------------------------------------|
| 定位 | UE 原生高画质新发行管线 | 既有轻量→中度→重度渐进发行管线 |
| 覆盖端 | L3 桌面/主机（UE） | L0 网页 / L1 Cocos小程序 / L2 Unity |
| 画质承诺 | 实时 3A（Sequencer/体积光） | 预渲染 CG 锚点 + 实时（按端分级） |
| 与生产矩阵关系 | 对齐 engine-pipeline-matrix L3 | 对齐既有 engine 三阶段迁移线 |
| 发布形态 | 原生安装包 / 云高配 | Web/H5/小程序/App |

> **关键**：两管线**共享同一套账号 + 存档 + 云会话协议**，仅表现端各自实现，杜绝四端四份烂摊子。这正是「版本并存可切、切换不重来」的架构核心。

### 2.2 各引擎接入统一协议边界

```
        ┌────────────────────────────────────────────┐
        │   game-protocols (统一 IDL, 跨引擎永远复用)      │
        │   账号协议 | 存档同步协议 | 云会话协议 | 下载状态  │
        └───────┬────────┬────────┬────────┬─────────┘
                │        │        │        │
          L0 网页    L1 Cocos   L2 Unity   L3 UE
          (TS)      (TS)       (C#)       (C++/BP)
        (protocol 生成 TS/C#/C++ 各语言绑定)
```

**对齐既有 `server/proto/protocol.proto`**（v1.0 · Issue #112 协议先行产物）：Platform 枚举已有 WEB/COCOS/UNITY/UE，GameStage 已有 COCOS→UNITY→UE 阶段感知。WP-02 在此之上**扩展发布转化相关消息**，遵循「字段只增不改、新增 optional、版本号递增」铁律。

### 2.3 跨引擎协议边界设计（建议新增 proto 增量草案）

| 协议 | 承载消息 | 字段边界（对齐 WP-01 策划 checkpoint） | 复用处 |
|------|---------|---------------------------------------|--------|
| 存档同步 | SaveSyncPush / SaveSyncPull | progress_checkpoint / platform / data_version / session_token | 切端续接，四端共用 |
| 云会话 | CloudSessionApply / Prewarm / Heartbeat / Release | session_id / stage / timeout_policy / bandwidth_budget | CG遮罩期预热、可中断、超时释放 |
| 下载状态 | DownloadStatus / ChunkComplete | download_id / chunk_index / bytes_done / resume_point | 边下边玩、断点续传 |
| 增强入口 | EnhancementRequest | from_state( LOCAL_LITE / CLOUD_PLAY ) / target_stage | 「增强画质」触发跳云 |

> 三套「永远复用」资产（存档/云会话/带宽）在本 WP 锚定 IDL 边界，跨引擎各端据此生成绑定代码，切换下载互不推翻。

## 三、带宽感知调度 + 下载分片/断点续传 + 无缝切换（client_dev · S-2.2）

### 3.1 带宽感知调度器（无状态纯算法资产 + 单测）

> 目标：防「云渲染限速 + 下载占满」双输。做成**无状态策略 + 单元测试**，跨引擎各端复用一个算法实现。

**调度策略（state machine）**：

```
输入: 云会话是否激活(is_cloud_active) / 当前下载进度(dl_pct) / 用户偏好(pref)
输出: 当前下载限速档位(dl_budget_ratio)

规则:
  if 云会话激活 && 下载中:
      dl_budget = 云渲染带宽预留后剩余带宽 的 60-70%   # 优先保 WebRTC QoS
      if 用户 pref = 画质优先:  dl_budget = 剩余带宽的 40-50%   # 更压下载
      if 用户 pref = 下载优先:  dl_budget = 剩余带宽的 80%      # 更快下完
  else:  # 云会话未激活 / 用户暂停云 / 切出标签页
      dl_budget = 100% 全速后台下载
输出同步: 写回 download_status.bandwidth_budget → 驱动客户端限速
```

**用户手动滑块**：提供「画质优先 / 下载优先」语义映射（对齐策划 WP-01 3.3），让用户按需调速。
**配套单测用例**（跨引擎复用）：
- 云激活 + 默认 → 限速 60-70% ✅
- 云激活 + 画质优先 → 限速 40-50% ✅
- 云关闭 → 全速 100% ✅
- 下载达 90%+ → 提前触发预释放信号 ✅

### 3.2 下载分片 / 断点续传（客户端管理）

| 能力 | 设计 |
|------|------|
| 分片下载 | 把本地完整包拆 N 个 chunk，后台顺序/并行拉取，逐 chunk 落盘并上报 ChunkComplete |
| 可中断 | 下载管理器支持暂停/取消（对齐策划可关下载），取消保留已下载分片 |
| 断点续传 | 重启/切换端后读 resume_point 从断点续传，不重头下 |
| 边下边玩 | 核心资源首包优先下载（保证能先玩），长尾资源后台慢下，实现「边下边玩」 |

### 3.3 无缝切换（云端 → 本地接管）

1. 切换触发点：本地下载达 **100%**（或达策划设的 90%+ 就绪阈值）
2. 过渡动画：统一「传送门 / 电梯 / 黑屏淡入」遮罩（对齐美术 CG 标准），掩盖加载差异
3. 存档接管：切换瞬间 **云端 SaveSyncPush → 本地 SaveSyncPull** → 从相同 progress_checkpoint 续玩
4. 视角续接：切换后前 30s 保持与云端相同相机位置/视角，避免跳转突兀（对齐架构师护栏）
5. 操作手感一致：云/本地按键映射、灵敏度、UI 布局完全一致（对齐架构师护栏）
6. 断网/手动回退：云会话中断 → 无缝回本地轻量版续玩（LocalLite 态），不报错退出

## 四、云会话服务端方案 + 成本控制（server_dev · S-2.3）

### 4.1 云会话生命周期（服务端状态机）

```
[Prewarm 预热池] ──(用户点增强/CG播放期后台静默申请)──► [Apply 申请] ──就绪──► [Active 会话中]
     ▲                                                                    │ 边下边玩
     │                                                                    ▼
     └─────────────[Release 释放] ◄── 超时/退出/下载90%+ 预释放 ◄──── [本地接管成功]
```

| 阶段 | 服务端动作 |
|------|-----------|
| 预热池 Prewarm | 维护常驻预热实例池（空闲可复用），CG 播放期静默申请，掩盖 5-15s 启动等待 |
| 心跳 Heartbeat | 客户端定期心跳保活，防僵尸会话占资源 |
| 超时策略 | 单次会话时长上限 30-60min（对齐策划护栏），超时提示「本地版即将就绪」并引导续下载 |
| 90% 预释放 | 本地下载达 90%+ 时主动提示「即将切换」并提前释放云实例（对齐策划 R5） |
| 可中断/回退 | 用户可随时退出云会话，云端存档回传本地，释放服务器资源 |

### 4.2 成本控制护栏

| 护栏 | 机制 |
|------|------|
| 预热池规模 | 按预估并发设置池上限，空闲超时回收 |
| 会话时长上限 | 30-60min 强制 + 引导下载完成转换 |
| 90% 预释放 | 下载接近完成即释放，避免长挂云端烧成本 |
| 新用户限制 | 对非付费/新用户限制云体验次数；老用户/预购开放更长（对齐策划/运营分流） |
| 差异化钩子 | 云体验版提供本地没有的内容（皮肤试用/剧情预览/多人片段）强化下载动机（对齐策划） |

### 4.3 自建 vs 接平台（决策待定 · 建议先锚协议不锁实现）

> 对齐架构师风险标注 [决策待定·需人拍板]：
> - 接平台（像素流网关/第三方云游戏）= 快但受制于平台
> - 自建 = 慢但可控
> **本 WP 阶段只锚云会话协议边界，不锁实现**。协议按「云实例 = 抽象资源单元」建模，无论自建/接平台都以统一 CloudSession ID 交互，后续实现可平替。

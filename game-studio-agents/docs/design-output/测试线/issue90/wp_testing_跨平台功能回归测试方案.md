# wp_testing · 跨平台功能回归测试方案（qa_engineer）

- **工作包**：wp_testing 跨平台回归/性能测试
- **部门**：测试线
- **主责角色**：qa_engineer（测试工程师·功能向）
- **模块**：testing / cross-engine-regression
- **产出物类型**：test_doc（跨平台回归测试方案）
- **场景**：Issue #90「跨平台架构增强」——在 Web→Cocos→Unity→UE 四级引擎间建立跨平台功能回归测试体系，验证四端功能一致性

---

## 一、回归测试范围

消费上游三大部门（策划/程序/美术）的全部 issue90 交付物，建立跨平台功能回归基线：

| 上游部门 | 输入文档 | 回归关注点 |
|---------|---------|-----------|
| 策划线 | wp_gameplay / wp_numeric_model / wp_combat / wp_narrative | 玩法逻辑四端一致、数值精度一致、战斗判定一致、叙事数据跨端同步 |
| 程序线 | wp_client / wp_server / wp_engine / wp_ai_logic | 客户端适配层功能、C ABI 接口、程序化生成确定性、服务端权威 |
| 美术线 | wp_art_direction / wp_ui_ux / wp_audio | 资源加载正确、UI 布局适配、音频播放一致 |

## 二、四端功能回归矩阵

### 2.1 引擎适配回归（IClientAdapter 接口）

| 回归用例 | Web(React) | Cocos | Unity | UE | 预期 |
|---------|:---------:|:-----:|:-----:|:--:|------|
| 引擎初始化/关闭 | ✅ | ✅ | ✅ | ✅ | 生命周期正常，无泄漏 |
| 场景创建/加载/卸载 | ✅ | ✅ | ✅ | ✅ | scene_id 正确，无重复创建 |
| 输入绑定/解绑 | ✅ | ✅ | ✅ | ✅ | 各端输入映射正确 |
| 资源加载/预加载 | ✅ | ✅ | ✅ | ✅ | 中立资产各端正常加载 |
| 网络连接/断开 | ✅ | ✅ | ✅ | ✅ | 四端连同一服务端 |

### 2.2 核心玩法逻辑回归

| 回归用例 | 覆盖设计 | 预期 |
|---------|---------|------|
| 核心玩法循环（规划→行动→构建→反馈） | wp_gameplay | 四端行为一致 |
| 战斗开始/结束/结算 | wp_combat | 结果由服务端权威判定，四端一致 |
| 资源产出/消耗 | wp_numeric_model | 数值精确，无浮点误差 |
| 任务状态机跨端同步 | wp_narrative | 状态切换广播一致 |
| NPC AI 行为（巡逻/攻击/追击） | wp_ai_logic | 行为树 JSON 驱动，四端一致 |

### 2.3 数据一致性回归

| 校验项 | 方法 | 容差 |
|--------|------|------|
| 定点数计算 | 同一操作在 4 引擎跑同一用例 | 结果 bit 级一致 |
| 随机种子确定性 | 同 seed → 4 引擎产出 | hash 完全一致 |
| 程序化生成输出 | 同 seed 地图/地形/关卡 | hash 完全一致 |
| 服务端权威回放 | 记录服务端操作日志 → 各端重放 | 状态一致 |
| 时间同步 | 服务端 tick 各端时钟 | ≤ 100ms 偏差 |

### 2.4 美术资源加载回归

| 校验项 | Web | Cocos | Unity | UE | 预期 |
|--------|:---:|:-----:|:-----:|:--:|------|
| glTF 模型加载 | ✅ | ✅ | ✅ | ✅ | 顶点数偏差 ≤2% |
| PNG 贴图采样 | ✅ | ✅ | ✅ | ✅ | ΔE ≤3 |
| 动画播放 | ✅ | ✅ | ✅ | ✅ | 时长偏差 ≤1帧 |
| WAV 音频播放 | ✅ | ✅ | ✅ | ✅ | 响度偏差 ≤1dB |
| UI 布局适配 | ✅ | ✅ | ✅ | ✅ | 设计令牌一致 |

## 三、回归测试执行策略

### 3.1 执行层级

```
L0（全量回归）：每次发布前执行，四端全量功能回归
L1（冒烟回归）：每日 CI，四端核心玩法冒烟
L2（专项回归）：引擎升级/适配层变更时触发，专项验证
```

### 3.2 测试数据

| 数据类别 | 来源 | 用途 |
|---------|------|------|
| 标准化测试 seed | wp_ai_logic 定义的 seed 池 | 程序化生成确定性验证 |
| 四端测试账号 | 服务端预置 | 多端并发/同步验证 |
| 美术测试资产 | wp_art_direction L0/L1 样例 | 资源加载回归 |

### 3.3 缺陷分级

| 级别 | 定义 | 处理 |
|------|------|------|
| 🔴 P0 阻塞级 | 核心功能不可用 / 数据严重不一致 / 安全问题 | 立即打回，阻塞发布 |
| 🟠 P1 严重 | 非核心功能异常 / 单端严重不一致 | 修复后回归 |
| 🟡 P2 一般 | 体验缺陷 / 非关键路径不一致 | 收集按批次修复 |
| 🔵 P3 建议 | 优化建议 | 记录待排期 |

## 四、回归测试准入/准出

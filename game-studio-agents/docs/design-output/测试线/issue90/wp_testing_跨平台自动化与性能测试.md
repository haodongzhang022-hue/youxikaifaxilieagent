- **主责角色**：auto_qa（自动化测试工程师·自动化与性能向）
- **模块**：testing / auto-framework + perf

### 1.2 测试用例定义格式（YAML）

```yaml
# 示例：程序化生成一致性用例
- id: PG-001
  type: consistency
  module: procgen
  engine: [web, cocos, unity, ue5]
  input:
    seed: "terrain_001"
    params:
      width: 100
      height: 100
  assert:
    method: hash_compare
    expected: null  # 四端自行比对
```

```yaml
# 示例：功能回归用例
- id: FUNC-001
  type: functional
  module: gameplay
  engine: [web, cocos]
  steps:
    - action: init_game
      params: { user: "test_user_001" }
    - action: start_combat
    - action: use_skill
      params: { skill: "fireball", target: "enemy_001" }
    - action: check_result
      params: { expected_damage: 150 }
```

### 1.3 断言库

| 断言类型 | 说明 | 示例 |
|---------|------|------|
| 值断言 | 精确值匹配 | `assert_eq(actual, expected)` |
| hash 断言 | 跨引擎 hash 一致 | `assert_hash(engine_results)` |
| 范围断言 | 性能指标范围 | `assert_lt(duration, 2000)` |
| 事件断言 | 异步事件触发 | `assert_event_emitted("combat_end")` |
| UI 断言 | 元素可见/存在 | `assert_visible("#btn_attack")` |

## 二、性能基准测试

### 2.1 性能指标定义

| 指标 | Web(React) | Cocos | Unity | UE5 | 测试方法 |
|------|-----------|-------|-------|-----|---------|
| **启动时间** | ≤ 2s | ≤ 3s | ≤ 5s | ≤ 8s | 冷启动计时 |
| **首帧渲染** | ≤ 1s | ≤ 1.5s | ≤ 2s | ≤ 3s | 首帧标记 |
| **FPS（战斗）** | ≥ 30 | ≥ 30 | ≥ 60 | ≥ 60 | 战斗场景实测 |
| **FPS（探索）** | ≥ 30 | ≥ 30 | ≥ 60 | ≥ 60 | 大世界探索 |
| **内存占用** | ≤ 200MB | ≤ 300MB | ≤ 1GB | ≤ 2GB | 任务管理器/Profiler |
| **加载时间** | ≤ 3s | ≤ 4s | ≤ 5s | ≤ 6s | 场景加载 |
| **网络延迟** | ≤ 200ms | ≤ 200ms | ≤ 100ms | ≤ 100ms | 服务端请求 |
| **帧率稳定性** | ≥ 95% | ≥ 95% | ≥ 97% | ≥ 97% | P95 < 100ms |

### 2.2 性能测试场景

| 场景 | 描述 | 性能关注点 |
|------|------|-----------|
| 战斗场景 | 50 单位同屏战斗 | FPS / 帧率稳定性 |
| 探索场景 | 大地图探索 | 加载时间 / 内存 |
| 程序化生成 | 随机生成地图 | 生成耗时 / GC 压力 |
| 多人在线 | 50 人同服 | 网络延迟 / 同步精度 |
| 资源加载 | 批量加载资产 | 加载时间 / 内存峰值 |

### 2.3 性能基准（Baseline）流程

```
1. 定义基准 → 记录首次性能数据（四端）
2. 持续监控 → CI 中每日自动跑性能用例
3. 对比分析 → 新版本 vs 基准，偏差 > 10% 触发告警
4. 回归门禁 → 性能劣化 > 20% 阻塞发布
```

## 三、CI 流水线集成

### 3.1 测试流水线阶段

| 阶段 | 触发 | 内容 |
|------|------|------|
| **L0 冒烟** | 每次 push | 核心功能冒烟 + hash 校验 |
| **L1 回归** | 每日定时 | 全量功能 + 兼容性矩阵 |
| **L2 性能** | 每周 | 四端性能基准对比 |
| **L3 发布门禁** | 版本发布前 | 全量 + 性能 + 一致性联合验收 |

### 3.2 CI 脚本结构

```bash
# test_pipeline.sh 核心逻辑
# 阶段 1: 冒烟测试
if [ "$STAGE" == "smoke" ]; then
    run_web_smoke() && run_cocos_smoke()
fi

# 阶段 2: 功能回归
if [ "$STAGE" == "regression" ]; then
    run_full_regression() && verify_consistency()
fi

# 阶段 3: 性能基准
if [ "$STAGE" == "performance" ]; then
    run_perf_baseline() && compare_with_baseline()
fi

# 阶段 4: 发布门禁
if [ "$STAGE" == "release" ]; then
    run_all_tests() && verify_gate()
fi
```

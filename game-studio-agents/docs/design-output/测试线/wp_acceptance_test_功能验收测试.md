# wp_acceptance_test · 全链路功能验收测试方案

- **工作包**：wp_acceptance_test 全链路功能验收测试
- **部门**：测试线
- **主责角色**：qa_engineer（测试工程师·功能向）
- **模块**：testing
- **产出物类型**：test_doc（测试方案）

## 一、验收范围

覆盖上游三大部门（策划/程序/美术）的全部交付物：

| 部门 | 交付物 | 验收维度 |
|------|--------|---------|
| 策划线 | 5 份设计文档 | 设计完整性 / 可实现性 |
| 程序线 | 5 个技术实现方案 | 功能正确性 / 接口契约 |
| 美术线 | 3 份美术方案 | 资源规范性 / 性能合规 |

## 二、功能验收用例

**核心玩法（gameplay）**：
- [ ] 核心循环完整可玩（规划→行动→构建→挑战→反馈）
- [ ] 战斗可正常开始/结束/结算
- [ ] 资源产出与消耗正确
- [ ] 任务系统可接受/推进/提交

**战斗系统（combat）**：
- [ ] 技能可正常释放（CD/消耗正确）
- [ ] 命中判定准确（前摇/后摇/无敌帧）
- [ ] NPC AI 行为正确（巡逻/攻击/追击）
- [ ] BOSS 三阶段切换正常

**剧情系统（narrative）**：
- [ ] 对话系统可正常推进
- [ ] 分支选择正确记录
- [ ] 任务条件可满足/判定

**数值经济（numeric_model）**：
- [ ] 货币/资源增减正确
- [ ] 交易流水 100% 可追溯
- [ ] 成长曲线符合设计

## 三、验收标准

- 功能通过率 ≥ 95%（阻塞级缺陷 = 0）
- 每个功能模块至少 5 个验收用例
- 接口契约 100% 符合文档定义

## 四、验收结论

- 全链路 3 部门交付物验收通过 → 解锁项目管理发版里程碑

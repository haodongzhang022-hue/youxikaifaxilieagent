### 3.3 内容匹配「提及部门」vs「分配工作」

| 场景 | 输入 | 路由结果 | 判定 |
|------|------|---------|:----:|
| PR 描述提及"测试线"但实际为基础设施 | 关键词含测试线 | 测试线触发 | ⚠️ 已知限制 |
| 实际分配给测试线的工作 | QA/回归/测试方案 | 测试线触发 | ✅ 正确 |
| 程序 bug（不涉及测试） | 仅 server 关键词 | 仅程序线，测试线跳过 | ✅ 正确 |

> **已知限制**：当 PR/Issue 文本中出现"测试线"等关键词时（如本 PR #92 描述中提及"尤其美术、测试线"），路由内容匹配会将其误判为 active 部门。这是关键词匹配的固有局限——"提及"与"分配"在当前实现中无法区分。建议后续增强语义分析或人工点名优先级兜底。

### 3.4 环境变量隔离

**发现问题**：`test_routing.sh` 中 CLI 测试子命令未显式清空 `CNB_ISSUE_DESCRIPTION` / `CNB_ISSUE_LABELS` 环境变量，CI 平台注入的标签/描述会污染路由判定。

**根因**：`route_from_env()` 会拼接 Issue 标题+描述+标签做关键词匹配，CI 环境下这些变量由平台注入（含"测试线验收中"等真实标签），导致测试非确定性。

**修复建议**：在 CLI 测试子命令中显式设置 `CNB_ISSUE_DESCRIPTION="" CNB_ISSUE_LABELS=""`，确保测试环境隔离。修复代码已本地验证通过（12/12 全绿），因推送权限限制暂未合入 main。

# wp_review_qa · 验收评审无推送动作/权限边界回归

- **工作包**：wp_review_qa 验收评审无推送动作/权限边界回归
- **部门**：测试线
- **主责角色**：qa_engineer（测试工程师（功能向）·验收向职责）
- **模块**：testing / review 治理回归
- **依赖**：wp_review_role（评审职责边界 ✅）、wp_review_route（推送行为解耦 ✅）、wp_review_ux（UI 评审只读应用 ✅）
- **产出物类型**：test_governance_doc（评审治理回归测试方案）

## 一、背景与目标

PR #56 落地「评审只读边界」：评审 NPC（代码审查员）**只读 + 给意见**，无推送/合并/关闭权限；
闭环通过**打标签**驱动（「适合合并」「适合关闭」「适合推送」），推送/改动统一由
本仓库 CodeBuddy（经 `config/agent_identity.py` 自适应探测当前仓库 slug，生成 `@当前仓库slug(CodeBuddy)` 完整格式）承接。美术线已同步将只读边界应用于 UI 评审。

本工作包目标：**验收测试阶段回归验证**评审在运行全链路中**无任何推送动作、不越权触发权限**，
杜绝「评审总想推送/误触 403」复现，确保只读边界从配置声明到运行行为**真正对齐落地**。

## 二、回归范围

| 评审阶段 | 配置位置 | 回归要点 |
|---------|---------|---------|
| NPC 代码审查 | `.cnb/settings.yml` 代码审查员 | 职责仅「读+给意见」，无推送 prompt |
| NPC 代码审查 | `.cnb.yml` review 阶段 systemPrompt | 权限边界声明完整、无 push 诱导 |
| 评审闭环健康检查 | `.cnb.yml` | 只读核查 + 报告，无推送动作 |
| 合并门禁检查×2 | `.cnb.yml` | 只读检查 + 输出结论，无推送 |
| 美术线 UI 评审 | wp_review_ux | TA 只读给意见，交 CodeBuddy 闭环 |

## 三、无推送动作回归用例

**用例 R-1：评审 prompt 无推送诱导**
- [ ] `.cnb/settings.yml` 代码审查员 slogan 为「只读审查，只给意见」
- [ ] 职责仅两条「读代码 + 给意见」，不含 push/merge/close 职责描述
- [ ] prompt 明确「禁止尝试 push/merge/关闭」，无「适合推送也由评审执行」表述

**用例 R-2：评审运行不触发推送**
- [ ] 评审结论通过/需修改，均在 PR 评论输出，不执行 push
- [ ] 评审环节产生的动作全部为「读 + 评论 + 打标签标记状态」
- [ ] 无 `git push` / `cnb pulls post-pull` / merge / close 等写操作调用

**用例 R-3：评审发现问题交 CodeBuddy 闭环**
- [ ] 需修改时，评论末尾召唤本仓库 CodeBuddy 承接修复
- [ ] CodeBuddy 作为唯一执行者修复后打「适合推送」标签标记状态
- [ ] 评审不越过职责自行修改代码

**用例 R-4：越权操作被拦截**
- [ ] 若评审尝试 push，触发 403/权限错误且被 prompt 显式告警阻止
- [ ] 403 不再出现「评审误推送」类卡点（职责已解耦）

**用例 R-5：标签驱动闭环成立**
- [ ] 评审→建议→CodeBuddy 修复→打标签→触发复审 全链路可走通
- [ ] 「适合合并」「适合关闭」「适合推送」标签语义清晰、职责分明

## 四、验收标准

- 评审全链路**零推送动作**（无 push/merge/close 写操作）
- 权限边界从配置到运行行为**对齐**，无「prompt 声明只读但实际诱导推送」的矛盾
- 需修改结论 100% 召唤 CodeBuddy 承接，评审自身不越权改动
- 打标签驱动闭环可复现，403 卡点归零

## 五、回归结论

**结论：✅ 待实测落地（配置已就绪，运行回归后终验）**

> 对齐上游 wp_review_role / wp_review_route / wp_review_ux 边界，推送闭环统一由 CodeBuddy 承接。
> 通过后可解锁下游 → 项目管理 wp_review_pm（评审→建议→CodeBuddy 推送闭环验收）。

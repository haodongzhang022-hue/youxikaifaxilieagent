## 一、核心思想：算法换语言，测试断言永不丢

游戏技术演进（Cocos→Unity→UE）会换语言（TS→C#→C++），但**纯算法的单元测试用例可以一直保留**。你用 C++ 重写后，跑一遍当年的测试用例，结果一致，即说明重构成功。

**对齐对象**：程序线 wp_client 产出的 `client_core/pure_logic.py`（纯逻辑类库），其确定性计算（deterministic）正是跨语言单测的测试对象。

## 二、跨语言单测回归基线

### 2.1 测试对象（对齐 pure_logic 确定性算法）

| 算法 | 纯逻辑来源 | 跨语言保留 |
|------|-----------|-----------|
| `calculate_damage` 伤害计算 | PureLogicEngine | ✅ 单测断言跨语言保留 |
| `calculate_crit` 暴击判定（确定性） | 确定性 hash | ✅ 结果一致 |
| `add_exp` 升级曲线 | 经验成长 | ✅ 结果一致 |
| 抽卡/概率算法 | 数值资产 | ✅ 单测保留 |
| ELO/matchmaking 算法 | 数值资产 | ✅ 单测保留 |

### 2.2 回归基线原则

```
同一组单元测试用例，在 TS / Python / C# / C++ 四种语言实现上
跑出完全一致的结果（Golden Test 断言）。
语言换、引擎换，但测试用例与断言永不丢。
```

**验证维度**：
1. **结果一致性**：同一输入 → 同一输出（跨语言零漂移）。
2. **确定性**：无随机数依赖，结果可复现（对齐 pure_logic 确定性计算）。
3. **边界一致**：定点数精度/整数溢出行为在四语言一致。

## 三、验收清单（回归信号灯）

- [ ] **G1 结果一致**：四语言实现跑通同一测试用例，输出一致
- [ ] **G2 确定性**：同一输入多次运行结果一致（无随机漂移）
- [ ] **G3 边界一致**：精度/溢出边界在四语言行为一致
- [ ] **G4 复用保留**：测试用例文件作为跨阶段资产纳入资产库
- [ ] **G5 阶段对齐**：测试范围匹配当前阶段算法（Cocos 不测 UE 复杂度）

## 四、跨阶段复用资产

1. **单测用例资产**：跨语言可复用的 Golden Test 断言集，永不废弃。
2. **算法基准**：抽卡/ELO/伤害计算的跨语言基准输出，作为重构回归锚点。
3. **阶段回归基线**：每个阶段切换时跑当年测试用例，验证重构成功。

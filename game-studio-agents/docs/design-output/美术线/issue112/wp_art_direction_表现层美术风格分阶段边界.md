## 〇、核心演进原则（贯穿四阶段）

Issue #112 核心思想是**"阶段不对就算错"**：Cocos 阶段上 UE 的美术管线=过度设计，
UE 阶段还抱 Cocos 的草台表现=技术债崩塌。本工作包把美术风格与表现层（动画/UI/特效）
做成**「引擎 × 阶段」二维坐标绑定**的边界矩阵。

三条贯穿铁律（承接上游策划/程序线，落到美术域）：
1. **逻辑与表现分离**：扣血（逻辑）≠ 播放爆炸动画（表现）。表现层只消费
   wp_client 的 `IPresentationAdapter` 事件，随引擎更换整体替换。
2. **阶段不过度设计**：当前阶段只做本阶段需要的美术能力，未来阶段的重构点明确标记。
3. **跨阶段资产复用**：美术风格规范、配色体系、UI 规范、动画手感基准、特效关键词
   跨引擎保留（仅实现层按引擎替换）。

## 一、四阶段表现层边界矩阵

| 表现维度 | 阶段1 Cocos(MVP) | 阶段2 Unity(商业化) | 阶段3 UE(3A) | 跨阶段复用资产 |
|---------|-----------------|--------------------|--------------|--------------|
| **美术风格规范** | 主基调定稿（色系/材质语言/光向） | 沿用以补细节，不推翻 | 沿用+极致化 | ✅ 风格指南 |
| **UI 复杂度** | 轻量 HUD + 基础界面 | 复杂 UI 框架（UGUI/FairyGUI） | 动态 UI + 全屏叙事 | ✅ 视觉规范 |
| **动画复杂度** | 2D 骨骼/基础切帧 | 3D 骨骼 + DOTween 补间 | 3D 高精 + 物理修正 | ✅ 手感基准 |
| **特效规模** | 轻量粒子（≤500/次） | 中量粒子 + 简单后处理 | 大量粒子 + 全后处理 | ✅ 特效关键词 |
| **性能预算** | 包体小、内存低 | 中高画质、热更新 | 极致画质、多端 | ✅ LOD 策略 |

## 二、四阶段美术风格分阶段边界（art_director）

### 阶段 1：Cocos / 小程序（MVP 验证期）

**阶段定位**：极速验证玩法，包体最小，表现从简。

| 维度 | 本阶段应做 | 标记"后期重构"（不做） |
|------|-----------|---------------------|
| 美术风格 | 定稿主色系（冷蓝/暖金/暗紫）+ 基础材质语言 | 不做 PBR 高精度贴图 |
| UI | 轻量 HUD（血量/技能/怒气）+ 基础界面 | 不做复杂动画 UI 框架 |
| 动画 | 2D 骨骼动画 / 简单切帧 | 不做 3D 高精骨骼 |
| 特效 | 轻量粒子（≤500/次）、无后处理 | 不做体积光/Bloom/后处理 |
| 资源规格 | sprite(.png) / audio(.mp3) / animation(.anim) | 不做 mesh/fbx/uasset |

**越界护栏**：Cocos 阶段禁止引入 UE 级 PBR 材质管线、高面数 mesh、全屏后处理 → 视为过度设计。

### 阶段 2：Unity / 团结引擎（商业化与中度游戏期）

**阶段定位**：提升画面表现力，复杂玩法，开始做热更新。

| 维度 | 本阶段应做 | 标记"后期重构"（不做） |
|------|-----------|---------------------|
| 美术风格 | 在阶段1基调上补材质细节、场景光照 | 不提前上 C++ 级内存池优化 |
| UI | UGUI/FairyGUI 复杂 UI 框架 + AssetBundle 热更 | 不做 UE 动态 UI 全屏叙事 |
| 动画 | 3D 骨骼动画 + DOTween 补间控制 | 不做物理修正级动作 |
| 特效 | 中量粒子 + 简单后处理（Bloom/色差可选） | 不做大世界级体积雾/流体 |
| 资源规格 | mesh(.fbx) / material(.uasset) / audio(.wav) | 不做 UE 蓝图 |

**平滑过渡**：此阶段 UI 视觉规范、动画手感基准、特效关键词必须与阶段1保持一致，
仅实现层从 TS/Cocos 切到 C#/Unity。

### 阶段 3：Unreal Engine（3A / 重度实时）

**阶段定位**：极致画质、大规模同屏、多端互通。表现层彻底质变。

| 维度 | 本阶段应做 | 重构来源 |
|------|-----------|---------|
| 美术风格 | 沿用四阶段基调，极致化（PBR 高精、动态天气） | 阶段2 基调整体升级 |
| UI | 动态 UI + 全屏叙事演出 | 阶段2 UI 规范重写为 UE 动态 UI |
| 动画 | 3D 高精骨骼 + 物理修正 + 表情/口型 | 阶段2 动画手感基准翻译为 C++ |
| 特效 | 大量粒子 + 全后处理（体积雾/流体/全局光照） | 阶段2 特效关键词升级 |
| 资源规格 | mesh/.uasset 高精 + C++ 源文件 | 新构建（UE 原生） |

### 阶段 4：终极形态 —— "一直能使用"的美术资产库

**目标**：建立跨阶段长期复用、永不废弃的美术核心资产。

- **美术风格指南**：色系/材质语言/光照方向/造型语言 —— 永不复用引擎，永远复用。
- **UI 视觉规范**：色彩/字体/图标/信息密度规范 —— 各引擎按规范实现。
- **动画手感基准**：前摇/后摇/命中停顿/无敌帧/弹反窗口 —— 各引擎实现手感一致。
- **特效关键词**：技能/受击/环境特效语义化描述 —— 各引擎翻译为对应粒子系统。

## 三、表现层引擎适配边界（tech_artist）

对齐程序线 wp_client 的 `IPresentationAdapter`，美术表现层只消费逻辑事件：

| 逻辑事件 | 表现层动作（引擎无关语义） | Cocos | Unity | UE |
|---------|--------------------------|-------|-------|-----|
| damage | 播放受击动画 + 飘血 | 2D 骨骼 | 3D 骨骼 | 高精+物理修正 |
| heal | 治疗特效 + 绿飘字 | 轻量粒子 | 粒子+简单后处理 | 全后处理 |
| level_up | 升级特效 + 全屏闪光 | 基础特效 | 粒子 | 体积光+粒子 |
| item_gain | 更新背包 UI | 基础 UI | 复杂 UI 框架 | 动态 UI |
| move | 更新角色节点位置 | 2D 节点 | 3D Transform | 高精骨骼 |

**技术美术护栏（tech_artist）**：
- 各阶段美术资源规范严格绑定引擎适配层 `engine_adapters.py` 的资源类型/扩展名/导入目录。
- 表现层组件只实现 `IPresentationAdapter` 接口，不触碰逻辑层（对齐 wp_client）。
- 阶段切换时仅替换表现层实现，逻辑层与美术规范零改动。

## 六、验收要点

1. **阶段不对就算错**：Cocos 阶段未上 UE 级美术管线；UE 阶段未抱 Cocos 草台表现。
2. **逻辑/表现分离**：表现层仅消费 `IPresentationAdapter` 事件，不触碰逻辑层。
3. **跨阶段资产复用**：风格指南/UI 规范/手感基准/特效关键词跨引擎保留。
4. **技术护栏**：美术资源规格绑定 engine_adapters，阶段切换仅换表现层。

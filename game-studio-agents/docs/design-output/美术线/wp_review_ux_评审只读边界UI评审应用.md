# wp_review_ux · 评审只读边界在 UI/交互评审中的应用

- **工作包**：wp_review_ux 评审只读边界在 UI/交互评审中的应用
- **部门**：美术线
- **主责角色**：tech_artist（技术美术 TA·管线向）
- **模块**：ui_ux / review 治理
- **依赖**：wp_review_role（评审角色职责边界声明 ✅）
- **产出物类型**：review_governance_doc（评审治理规范文档）

## 一、背景与目标

PR #56 落地了「评审只读边界」：评审（代码审查员）**只读 + 给意见**，不推送、无权限操作，
推送/改动统一由 `@dongdongxiaozu/youxikaifaxilieagent(CodeBuddy)` 承接闭环。

美术线 UI/交互评审同样是**只读监督**环节——TA（tech_artist）作为美术与程序之间的
桥梁，在 UI/交互方案评审中必须贯彻同一原则：**只读 + 给意见**，不改动、不推送、
不越权执行，把「适合改」的结论交给下游 CodeBuddy 承接，职责分明、闭环一致。

## 二、评审只读边界在 UI/交互评审中的应用原则

### 1. 评审角色边界（与 wp_review_role 对齐）
| 动作 | 是否允许 | 说明 |
|------|---------|------|
| 阅读 UI/交互方案与资源 | ✅ 允许 | 方案/资源/数据只读 |
| 给出意见/建议 | ✅ 允许 | 描述「应该改成什么样」 |
| 修改 UI/资源文件 | ❌ 禁止 | 改动交由 CodeBuddy 执行 |
| 推送/合并/关闭 | ❌ 禁止 | 无推送权限 |
| 越权评审他人部门产出 | ❌ 禁止 | 只评审本部门职责范围 |

### 2. UI/交互评审意见规范（readonly review 模板）
评审意见必须**只读输出**，统一为「三要素」格式：
```
位置/对象：UI 界面/交互流程中的具体节点
现状：当前行为（客观描述）
建议：应该改成什么样（交给 CodeBuddy 承接执行）
```
> 例：`位置：技能冷却提示条 / 现状：命中反馈仅在 0.3s 后显示 / 建议：改为命中瞬间 0.05s 顿帧+闪光提示`

### 3. 与 CodeBuddy 的职责闭环
- TA 评审**只给意见**，不直接改 UI/Shader/资源；
- 「适合改」的结论召唤本仓库 CodeBuddy 承接执行：
  `@dongdongxiaozu/youxikaifaxilieagent(CodeBuddy)`
- 形成「评审只读 → 建议描述 → CodeBuddy 推送闭环」，杜绝 TA 越权推送/误触 403。

## 三、UI/交互评审只读清单（美术线内应用）

| 评审对象 | 只读检查项 | 产出（意见而非改动） |
|---------|-----------|---------------------|
| 界面布局 | 与策划玩法/系统对齐 | 布局调整建议 |
| 交互流程 | 操作路径是否顺畅、无阻塞 | 交互优化建议 |
| UI 特效反馈 | 反馈节奏是否符合打击感/沉浸感 | 特效/动效建议 |
| 界面视觉 | 与世界观风格一致性 | 视觉统一建议 |
| 性能约束 | Draw Call / 内存 / 加载耗时 | 性能优化建议（交由 CodeBuddy 落地） |

## 四、性能与合规约束（TA 把关项）
- 评审给出的建议不得隐含推送/权限越权动作；
- UI 性能建议（Draw Call、纹理压缩、合批）仅作为意见输出，落地由 CodeBuddy 执行；
- 全程经协作工作台留痕（group_audit），评审动作可审计、可回退。

## 五、验证指标
- ✅ 评审动作全部为只读（无改动/推送/合并）
- ✅ 每条意见含「位置/现状/建议」三要素，可直接交给 CodeBuddy 承接
- ✅ 与 wp_review_role / wp_review_route 边界一致，推送闭环统一由 CodeBuddy 承接

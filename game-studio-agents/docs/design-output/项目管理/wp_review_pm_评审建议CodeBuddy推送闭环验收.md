## 一、验收目标

验证评审-修复闭环**「评审只读 → 描述建议 → CodeBuddy/仓库处理专员 修复推送」**完整链路，
确保评审职责边界（只读+给意见，不推送）从配置声明到运行行为真正对齐，杜绝评审越权推送。

## 二、闭环链路逐项验收

### 验收点 1：评审只读（读 + 给意见，不推送）✅
- `.cnb/settings.yml` 代码审查员 slogan =「**只读审查，只给意见**」；
- 职责仅「读代码 + 给意见」，权限边界声明明确：**不得自己动手**修复/打标签/合并/关闭；
- 无 push / merge / close 职责描述，prompt 无推送诱导。

### 验收点 2：描述建议（评审结论在评论输出）✅
- 评审通过/需修改均以**评论**输出结论与建议，动作全为「读 + 评论 + 打标签标记状态」；
- 需修改时评论末尾召唤本仓库仓库处理专员/CodeBuddy 承接修复。

### 验收点 3：CodeBuddy/仓库处理专员 修复推送（闭环承接）✅
- `review-fix-loop` 闭环完整：**测试信号灯 → 自动分配评审人 → NPC 代码审查 → 仓库处理专员闭环修复 → 评审闭环健康检查 → 合并门禁检查**；
- 修复完成后**打「适合推送」标签**标记状态（标签驱动，无 push 依赖），打标签触发**下一轮**评审；
- 本系统故意设计不允许 push，闭环全部经打标签驱动，403 卡点归零。

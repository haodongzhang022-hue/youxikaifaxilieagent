## 二、职责边界与闭环逐项验收

### 验收点 1：仓库处理专员 = 本仓库唯一打标签执行者 ✅
- `.cnb/settings.yml` 第 139 行正确注册**仓库处理专员**角色，slogan「打标签唯一执行者（标签驱动，禁止 push）」；
- 明确**唯一**有权限打「适合推送」/「适合合并」/「适合关闭」标签的角色；
- 其他角色（CodeBuddy / 代码审查员 / 游戏向经理 / 各线部门）**只提供信息和建议，不执行打标签**；
- 其他角色发现需打标签时必须召唤仓库处理专员处理。

### 验收点 2：标签驱动闭环成立 ✅
- 修复完成 → 打「适合推送」标签 → 触发**下一轮**评审；
- 评审通过 → 打「适合合并」标签 → 进入合并门禁；
- 无法解决 → 打「适合关闭」标签 → 标记关闭；
- **本系统故意设计不允许 push**，闭环全程经打标签驱动，无 push 依赖、403 卡点归零。

### 验收点 3：召唤优先级链生效 ✅
- `agent_identity.py` 固化召唤优先级链：**仓库处理专员 → CodeBuddy（逐个降级）**；
- 默认优先召唤仓库处理专员，其不可用/权限不足时降级 CodeBuddy（仅建议、不执行打标签）；
- **同一时刻只召唤一个角色**，符合触发安全控制。

### 验收点 4：PR #59/#64 冲突处置验收 ✅
- PR #59（禁止评审输出推送内容）与 PR #64（裸 @CodeBuddy 召唤）均基于旧版本回退，与主线 PR #52「仓库处理专员优先 + 带壳完整格式召唤」语义矛盾；
- 已核验：**PR #59 与 PR #64 均 `state: closed`、`is_merged: false`、`mergeable_state: conflict`**；
- 处置结论：**保留主线架构，关闭/废弃 PR #59/#64**，避免强行合并回退方向冲突。

## 一、核心思想：数值复杂度匹配阶段目标

数值/经济系统不能"一步到位"，否则会在早期阶段引入大量无用复杂度：
- **阶段1 Cocos**：只做单一货币 + 基础成长，快速验证。
- **阶段2 Unity**：多货币 + 商城 + 抽卡，支撑商业化。
- **阶段3 UE**：复杂经济 + 跨服 + 深度养成，支撑 3A 长线。
- **阶段4 资产库**：数值配置表资产跨引擎永远复用。

## 二、四阶段数值复杂度模型

| 数值维度 | 阶段1 Cocos/MVP | 阶段2 Unity/商业化 | 阶段3 UE/3A | 跨阶段资产 |
|---------|----------------|-------------------|-------------|-----------|
| 货币体系 | 单一货币 | 硬+软双货币 | 多货币+跨服经济 | 货币协议 |
| 成长曲线 | 基础等级 | 等级+星级+装备 | 深度养成+天赋 | 成长曲线配置 |
| 抽卡/概率 | 简易掉落 | 抽卡+保底 | 复杂概率+跨服 | 概率算法单测 |
| 经济结算 | 服务端统算 | 防刷+幂等 | 跨服结算 | 结算协议 |
| 数值精度 | 定点数(1/1000) | 整数+定点 | 高精度 C++ | 精度基准 |

## 三、防膨胀规则（阶段护栏）

```python
# 阶段数值膨胀检查（对应 config/stage_aware_engine.py 越界检测）
guard.check('multi_currency_shop', GameStage.STAGE1_COCOS)
# -> 命中"边界外"：Cocos 阶段不该引入多货币商城，标记后期重构
```

**防膨胀护栏**：
- [ ] 本阶段数值维度是否超出阶段目标（MVP/商业化/3A）所需？
- [ ] 数值精度是否统一（跨端一致性，对齐 wp_client 纯逻辑层）？
- [ ] 核心经济是否服务端权威结算（防刷）？
- [ ] 是否过早引入 UE 阶段的深度养成复杂度？

## 四、跨阶段复用资产

1. **数值配置表资产（Excel → JSON/Binary）**：Cocos 用 TS 读、Unity 用 C# 读、UE 用 C++ 读，策划几年的心血不因换引擎丢失。
2. **纯算法资产（伪代码 → 各语言实现）**：抽卡/ELO 算法跨语言保留，单元测试用例一直保留。
3. **数值基准协议**：货币/结算结构化定义，跨引擎一致。

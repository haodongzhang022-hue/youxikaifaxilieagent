## 一、核心思想：玩法/系统按引擎层级差异化设计

Issue #126 核心诉求：**不同引擎层级应按对应游戏开发深度组织玩法/系统设计**，而非用统一笼统的输出抹平差异。

| 引擎层级 | 定位 | 玩法深度 | 系统复杂度 | 目标用户 |
|---------|------|---------|-----------|---------|
| L0 纯网页 | 轻量验证 / 休闲吸量 | 轻操作、单局快、社交裂变 | 单货币 + 基础成长 | 泛用户 |
| L1 Cocos | MVP / 小程序渠道 | 休闲→中度过渡、留存导向 | 双货币 + 基础养成 | 中度玩家 |
| L2 Unity | 商业化 / 长线运营 | 中度深度、内容驱动 | 多货币 + 商城 + 赛季 | 商业化玩家 |
| L3 UE | 3A / 开放大世界 | 硬核实时、沉浸叙事 | 复杂经济 + 跨服 | 硬核玩家 |

## 二、核心循环按引擎层级分化

```
L0 纯网页：进入 → 轻操作 → 即时反馈 → 分享回流
L1 Cocos ：登录 → 关卡推进 → 资源收集 → 角色成长 → 分享回流
L2 Unity ：规划 → 战斗/采集 → 构建/养成 → 挑战 → 社交互动
L3 UE    ：探索 → 任务链 → 战斗 → 建造/升级 → 剧情 → 大世界互动
```

**设计原则**：低层级循环简单直接、单局时间短；高层级循环深度递进、单局时间长、模块间耦合更丰富。

## 三、系统树按引擎层级适配

| 系统模块 | L0 纯网页 | L1 Cocos | L2 Unity | L3 UE |
|---------|----------|----------|----------|-------|
| 核心玩法 | 单机制休闲 | 关卡+资源 | 战斗+采集+养成 | 开放大世界+任务链 |
| 成长系统 | 单线等级 | 等级+装备 | 等级+技能+天赋 | 深度养成+转职 |
| 经济系统 | 单一货币 | 硬/软双货币 | 多货币+商城+抽卡 | 复杂经济+跨服交易 |
| 社交系统 | 好友+分享 | 排行榜+好友 | 公会+组队+聊天 | 跨服阵营+家园 |
| 任务系统 | 简单引导 | 主线+支线 | 主线+支线+日常 | 全区域任务链+成就 |
| 战斗系统 | 无/简化 | 自动战斗 | 即时战斗+技能 | 帧同步硬核+物理 |

## 四、系统树结构（system_tree）

```
┌─ 核心玩法层 ─ 由引擎层级决定深度（L0~L3）
│   ├─ 战斗系统（见 wp_combat 分层设计）
│   ├─ 关卡系统（按引擎层级设计线性/章节/大世界）
│   └─ 探索系统（L2/L3 引入，L0/L1 仅做轻量）
├─ 成长层 ─ 随引擎层级增加深度
│   ├─ 等级系统（全层级基础）
│   ├─ 技能/天赋（L1+ 引入）
│   ├─ 装备/养成（L2+ 引入）
│   └─ 转职/深度养成（L3 引入）
├─ 经济层 ─ 复杂度匹配引擎层级（见 wp_numeric_model）
├─ 社交层 ─ L0 轻社交 → L3 深度社交
└─ 表现层 ─ 由引擎能力决定（纯网页极简 → UE 全 3D）
```

## 五、引擎层级玩法适配清单

**L0 纯网页**：
- [x] 单机制核心循环，操作 ≤ 2 键位
- [x] 关卡数量精简（5~10 关 MVP 验证）
- [x] 进度即云端存档，断点续玩
- [x] 分享回流是唯一社交入口

**L1 Cocos**：
- [x] 双货币体系，基础养成（等级+装备）
- [x] 章节式关卡 + 难度梯度
- [x] 自动战斗/半自动战斗（降低上手门槛）
- [x] 好友+排行榜轻社交

**L2 Unity**：
- [x] 即时/半即时战斗 + 技能组合
- [x] 多货币 + 商城 + 抽卡商业化
- [x] 公会 + 组队 + 聊天完整社交
- [x] 赛季/通行证长线内容

**L3 UE**：
- [x] 开放大世界 + 帧同步硬核实时
- [x] 复杂经济 + 跨服交易
- [x] 深度养成 + 转职 + 家园
- [x] 沉浸叙事 + 大世界任务链

## 六、系统模块化原则

1. **逻辑与表现分离**：玩法核心逻辑引擎无关，表现层由各引擎适配器处理
2. **按需挂载**：系统按引擎层级挂载，L0 不加载 L3 系统
3. **配置驱动**：系统开关/参数通过配置表控制，避免代码分支
4. **数据协议化**：系统间通信走结构化协议，不直接耦合

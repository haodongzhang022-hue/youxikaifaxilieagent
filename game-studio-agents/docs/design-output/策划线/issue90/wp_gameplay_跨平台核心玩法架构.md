## 一、核心玩法架构（引擎无关抽象层）

**设计原则**：玩法逻辑与引擎渲染/输入完全解耦，通过**抽象接口层**（IEngineAdapter）桥接。

### 1.1 分层架构

```
┌─────────────────────────────────────────────┐
│  玩法逻辑层（Engine-Agnostic Pure Logic）    │
│  · 核心循环状态机                          │
│  · 规则引擎（纯逻辑，无渲染/输入依赖）       │
│  · 程序化生成算法（纯数据输出）              │
├─────────────────────────────────────────────┤
│  引擎适配层（Engine Adapter Interface）     │
│  · IInputAdapter  输入抽象（触摸/键鼠/手柄） │
│  · IRenderAdapter 渲染抽象（场景/UI/特效）  │
│  · IAssetAdapter  资源加载抽象              │
│  · IAudioAdapter  音频播放抽象              │
│  · INetworkAdapter 网络通信抽象             │
├─────────────────────────────────────────────┤
│  引擎实现层（Web / Cocos / Unity / UE）     │
│  · React 实现（网页引流）                  │
│  · Cocos 实现（小程序快速分享）             │
│  · Unity 实现（完整内容）                  │
│  · UE 实现（高质量护城河）                  │
└─────────────────────────────────────────────┘
```

### 1.2 核心玩法循环（引擎无关版）

采用 **「规划 → 采集/行动 → 构建/成长 → 挑战 → 反馈」** 五段式循环，状态机以纯数据驱动：

| 阶段 | 引擎无关行为 | 引擎层行为（桥接） |
|------|-------------|------------------|
| 规划 | 玩家策略选择（纯逻辑） | UI 面板渲染 |
| 采集/行动 | 资源采集/战斗判定（逻辑层） | 场景加载 + 角色动画 |
| 构建/成长 | 属性/装备计算（逻辑层） | 数值特效播放 |
| 挑战 | 战斗结算 + 难度适配（逻辑层） | 战斗特效 + 音效 |
| 反馈 | 奖励结算 + 成就判定（逻辑层） | 奖励动画 + 推送 |

### 1.3 程序化生成引擎无关标准

程序化生成作为跨平台核心基建，所有生成算法输出**结构化数据**而非引擎对象：

```json
{
  "map_type": "floating_island",
  "seed": 421876,
  "terrain": {"width": 128, "height": 128, "layers": ["rock", "grass"]},
  "spawn_points": [{"x": 12, "y": 34, "type": "player"}],
  "resources": [{"x": 56, "y": 78, "type": "star_core", "amount": 5}],
  "enemies": [{"x": 23, "y": 45, "type": "void_wisp", "level": 3}]
}
```

- 生成数据 → 各引擎适配器转换为引擎原生对象（Prefab / Scene / Actor）
- 同一 seed 在所有引擎产出**一致的地图布局**，保证跨平台体验统一
- 素材复用：生成算法只依赖基础图元库（砖块/植被/地形块），支持多引擎共享资源

## 二、系统架构（多端模块解耦）

### 2.1 模块划分（引擎无关 × 引擎相关）

| 系统模块 | 引擎无关层 | 引擎相关层 | 解耦策略 |
|---------|-----------|-----------|---------|
| 核心玩法系统 | 状态机/规则引擎 | 场景管理/战斗动画 | 纯逻辑接口 |
| 成长系统 | 属性计算/等级公式 | UI 渲染/升级特效 | 数值驱动 |
| 经济系统 | 资源增减/交易逻辑 | 商城界面/购买弹窗 | 数据表驱动 |
| 社交系统 | 好友/组队/排行逻辑 | 聊天 UI/头像渲染 | 服务端驱动 |
| 任务系统 | 任务状态机/进度 | 任务面板/指引动画 | 数据驱动 |
| 养成系统 | 养成规则/解锁条件 | 养成动画/展示 | 配置表驱动 |

### 2.2 多端一致性保障

| 保障项 | 策略 | 实现方式 |
|-------|------|---------|
| 玩法一致性 | 核心逻辑统一在 C++ 层 | 跨引擎共用 C++ 中间件（ABI 标准化） |
| 数值一致性 | 数值计算走统一 C++ 实现 | 避免浮点误差导致多端差异 |
| 时间一致性 | 服务端权威时间戳 | 客户端只做表现层插值 |
| 随机一致性 | 统一随机种子管理 | 程序化生成/战斗掉落共用种子 |
| 状态同步 | 服务端状态机统一 | 多端只做状态表现 |

## 三、跨平台程序化生成设计（引擎无关）

### 3.1 生成管线

```
[种子] → [地形生成] → [资源分布] → [敌人布点] → [结构数据] → [各引擎适配器] → [场景]
```

### 3.2 生成算法清单

| 算法 | 输出 | 引擎无关性 |
|------|------|-----------|
| 噪声地形（Perlin/Simplex） | 高度图数组 | ✅ 纯算法 |
| 房间/路径生成 | 节点图数据结构 | ✅ 纯算法 |
| 资源分布（基于噪声阈值） | 坐标+资源类型列表 | ✅ 纯算法 |
| 敌人波次生成（难度曲线驱动） | 敌人配置表 | ✅ 纯数据 |
| Boss 区域生成 | 区域配置 + 触发条件 | ✅ 纯数据 |

### 3.3 素材复用策略

- 基础素材库以通用格式存储（PNG/MP3/FBX），各引擎适配器负责转换
- 程序化生成不直接引用引擎对象，只引用素材 ID 与变换参数
- 素材分级：L0（通用像素素材，所有引擎可用）/ L1（半通用）/ L2（引擎专属高保真）

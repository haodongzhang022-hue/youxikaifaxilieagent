# wp_gameplay · 玩法/系统架构设计

- **工作包**：wp_gameplay 玩法/系统架构设计
- **部门**：策划线
- **主责角色**：lead_designer（主策划·结构型） + system_designer（系统策划）
- **模块**：gameplay
- **产出物类型**：design_doc（设计文档）

## 一、核心玩法循环（core_loop）

采用「规划 → 采集/行动 → 构建/成长 → 挑战 → 反馈」五段式核心循环，保证可玩性与长期留存：

1. **规划**：玩家基于当前目标制定行动策略
2. **采集/行动**：在环境中执行采集、战斗、探索等行为
3. **构建/成长**：利用资源升级角色/基地/装备
4. **挑战**：投入成长成果挑战更高难度内容
5. **反馈**：获得奖励与成就反馈，驱动下一轮规划

## 二、系统架构（system_arch）

| 系统模块 | 功能定位 | 关联系统 |
|---------|---------|---------|
| 核心玩法系统 | 战斗/采集/探索主循环 | 全部 |
| 成长系统 | 角色等级/技能/装备 | 战斗、数值 |
| 经济系统 | 资源产出/消耗/交易 | 数值、商业 |
| 社交系统 | 组队/好友/排行 | 成长、经济 |
| 任务系统 | 主线/支线/日常引导 | 剧情、关卡 |
| 养成系统 | 长期目标与碎片化成长 | 数值、付费 |

## 三、核心功能清单（feature_list）

- 核心系统：战斗循环、资源产出、角色成长、任务引导
- 子系统：社交、排行榜、成就、商店、赛季

## 四、设计要点

- 系统间依赖单向化，避免循环耦合，便于模块化开发与调优
- 核心循环中的每个环节都绑定数值反馈，保证「行为→奖励」闭环清晰
- 系统架构采用「主循环驱动 + 子系统挂载」模式，便于后续扩展新玩法

> 产出：主策划 lead_designer 承接，经协作工作台 @分工 拆派 system_designer 细化系统规则。

# WP-01 · 多引擎管线需求汇总 + 体验转化漏斗方案（Issue #135）

> 承接：策划线（部门级 · lead_designer + system_designer）
> 上游蓝图：游戏架构师「多引擎并行生产之上叠加多引擎并行发行」的第二正交轴——发布转化管线
> 定位：**方案储备**。本 WP 聚焦「需求汇总 + 体验漏斗设计」，供程序线(WP-02)/美术线(WP-03)/项目管理(WP-04) 承接排期与实现，**非本部门全量落地云渲染**。

---

## 〇、一句话结论

> 玩家应能**从最轻入口进来，在“体验-转化”漏斗里无感滑向最适合自己设备/网络/喜好的引擎版本**；
> 四个引擎版本（网页 / 小程序 / 团结 / 虚幻）**同产同发、并存可切**；
> 转化过程把「等待下载」从流失点反转为转化点（边下边玩、可随时退出下载）。

---

## 一、需求汇总（多引擎管线）

### 1.1 顶层需求（来自架构师蓝图 + 原始诉求）

| # | 需求 | 说明 |
|---|------|------|
| R1 | 多引擎版本并存 | 网页 / 小程序 / 团结 / 虚幻 四版同产同发，供玩家按设备/网络/偏好自选 |
| R2 | 版本可切换下载 | 各引擎版本互相切换下载，不互相推翻 |
| R3 | 体验转化漏斗 | 低门槛吸入 → 内容钩子 → 高画质锚点 → 云高配试玩 → 本地无缝接管 |
| R4 | 存档/账号/云会话一致 | 四版本共享同一账号体系与存档，切端可续接（跨引擎永远复用资产） |
| R5 | 成本可控 | 云实例预热池 / 会话时长上限 / 下载 90%+ 预释放 |
| R6 | 带宽防双输 | 云渲染时下载自动限速，带宽感知调度 |

### 1.2 分阶段落地（阶段合规 · 储备而非全量硬做）

| 阶段 | 可落内容 | 归属 |
|------|---------|------|
| **现在（MVP 可落）** | L0/L1 轻量版（网页/小程序）入口 + 过场 CG 高画质锚点 + 「点增强跳云」Demo 桩 | 本方案给出设计基线 |
| **UE 阶段储备** | 真云渲染/像素流 + 无缝切换 | 方案设计先行，落地留储备 |
| **永远复用资产** | 账号/存档/云会话三套协议 IDL + 带宽感知调度策略 | 立即锚定边界 |

### 1.3 对策划线的影响（本部门职责范围）

- **玩法差异**：各引擎版本的「玩法深度」须差异化但核心循环同一（L0 极简 → L3 3A）
- **进度续接**：云/本地切换点必须保证「玩家进度一致」，需定义**存档同步协议**（策划侧进度字段边界）
- **数值体验**：云高配与本地低配的画质/手感差异不得破坏核心战斗手感与数值公平性

## 二、体验转化漏斗总纲（lead_designer）

### 2.1 漏斗五环节定义

```
① 低门槛入口         ② 画质锚点            ③ 云高配试玩           ④ 本地接管
 玩家(网页/小程序) →  播放过场CG            点击「增强画质」     →  下载完成无缝接管
 秒开即玩,获客最宽    展示目标画质,成本低    (边下边玩/可退出)    进度/视角续接
        │                │                    │                    │
        ▼                ▼                    ▼                    ▼
  获客环节(无门槛)     锚定/说服环节(低成本)  转化/留存环节(核心创新) 沉淀/拥有环节(本地留存)
```

### 2.2 漏斗设计要点

| 环节 | 设计目标 | 策划侧要点 |
|------|---------|-----------|
| ① 低门槛入口 | 获客门最宽、秒开 | 轻量版是完整玩法的「可玩预告」，非阉割体验；首包小 |
| ② CG 画质锚点 | 展示目标画质、遮盖云启动等待 | CG 是「画质承诺」，需与实机目标画质一致，避免落差 |
| ③ 云高配试玩 | 把等待反转为转化点 | 云体验期提供差异化内容钩子（专属皮肤试用/剧情预览） |
| ④ 下载+无缝接管 | 边下边玩、可关下载、断点续传 | 接管点进度/视角/操作手感一致，过渡动画统一 |

### 2.3 关键护栏（策划视角）

- **[MED] 画质落差**：CG 锚点画质与云实机、本地实机三级需收敛，落差过大会造成「被广告骗」的反感
- **[LOW] 成本失控**：云体验设单次时长上限（30–60min），90%+ 下载完成主动预释放云实例
- **[MED] 云/本地公平性**：云与本地数值/规则一致，仅画质/操作手感差异，不产生「充值落差」

## 三、漏斗各环节系统定义（system_designer）

### 3.1 状态机（下载-云-本地 三态互切）

```
                    ┌──────────────────────────────────────────┐
                    ▼                                          │
[① 本地轻量版] ──点击「增强画质」──► [② CG锚点播放]              │ 云会话
     ▲                                │(后台静默申请云实例)      │  超时/退出
     │                                ▼                         │
     │          [③ 云高配试玩(边下边玩)] ◄──下载>0% 允许中途退出──┘
     │             │ 下载达 100%
     │             ▼
     │          [④ 本地完整接管] ──(后续本地启动不再经云)
     └──────── 云会话优雅断开,进度回传本地 ◄──(断网/手动回退)──┘
```

### 3.2 状态与关键字段（策划侧数据表边界）

| 状态 | 触发 | 退出条件 | 策划关注字段 |
|------|------|---------|------------|
| LOCAL_LITE | 首次进入（网页/小程序） | 点击「增强画质」 | 本地进度 checkpoint |
| CG_ANCHOR | 点击增强 | CG 播完 / 云就绪 / 用户跳过 | CG 是否已看（可跳过） |
| CLOUD_PLAY | 云实例就绪 | 下载 100% / 会话超时 / 用户退出 | 云内进度 + 差异化内容 |
| LOCAL_FULL | 下载完成无缝接管 | 无 | 接管进度 = 云进度 |

### 3.3 系统模块边界

| 模块 | 归属（程序线 WP-02 细化） | 策划线定义输入 |
|------|--------------------------|---------------|
| 存档同步协议 | game-protocols（跨引擎） | 进度 checkpoint 字段边界 |
| 云会话协议 | game-protocols | CG 时长上限、云会话超时策略 |
| 带宽感知调度 | 纯算法资产 | 「下载优先/画质优先」用户滑块语义 |
| 下载分片/续传 | 中间件 | 可中断下载的体验文案规范 |

### 3.4 文案与引导（供美术线 CG / 程序线 UI 对接）

- **增强入口文案**（A/B 待测）：「解锁 4K 画质 / 体验完整剧情 / 免费试玩正式版」
- **云体验中提示**：「本地完整版后台下载中（xx%）」「画质优先 / 下载优先」
- **接管提示**：「正在切换到本地版本…」过渡动画（统一传送门/淡入淡出）
- **断网回退**：云中断 → 无缝回本地轻量版续玩，不报错

## 五、结论

- 本方案为**多引擎并行发行的「体验转化漏斗」提供策划需求总纲与系统状态定义**
- 落地按阶段：MVP 落 ①轻量版→②CG→③云 Demo 桩；真云渲染留 UE 阶段储备
- 存档/云会话协议字段边界为跨引擎永远复用资产，建议即刻与程序线对齐定 IDL

# 多引擎流水线架构设计（Multi-Engine Pipeline Architecture）

> 版本: v1.0  
> 对齐 Issue #90：React→Cocos→Unity→Unreal 四级引擎流水线 + 跨引擎中间件 + AI 协作加速  
> 核心命题：**灵活的引擎迁移能力优先，持续建设项目基建**

---

## 一、架构八步 · 调研结论

### 1.1 业务需求分析

| 层级 | 引擎 | 定位 | 核心目标 | 技术栈 |
|------|------|------|---------|--------|
| **L1 引流层** | React (Web) | 玩法验证 + 引流分享 | 最敏捷开发、快速验证玩法、网页传播 | React + Canvas + WebGL |
| **L2 轻量层** | Cocos Creator | 小程序/轻量游戏 | 快速分享传播、轻量包体、微信小程序 | TypeScript + Cocos 引擎 |
| **L3 完整层** | Unity (团结引擎) | 完整地图/App客户端 | 完整游戏体验、程序化生成、内容升级 | C# / C++ + 团结引擎 |
| **L4 护城河** | Unreal Engine | 高品质效果 | 视觉/物理天花板、护城河 | C++ + UE5 |

### 1.2 核心驱动因素

1. **引擎频繁更换** → 需要跨引擎迁移的复用工具层（中间件）
2. **素材通用复用** → 需要中立资产格式 + 程序化生成管线
3. **AI 协作编程** → Python→C++ 转译 + 大量 AI 辅助代码生成
4. **快速试错** → 每级引擎投入成本递增，需逐级验证
5. **C++ / C ABI 选型** → 提升泛化能力、方便向 UE 转移、通用性高

### 1.3 关键假设与风险

| 假设 | 风险等级 | 应对 |
|------|---------|------|
| C++ + C ABI 可同时服务 Unity/UE | LOW | C ABI 是 C++ 子集，天然通用；需注意 Unity 用 C++ 需要 IL2CPP 或 Native Plugin |
| 程序化生成可跨引擎复用 | MEDIUM | 程序化生成代码需引擎无关化（数据驱动 + 中立格式） |
| React 玩法可映射到 Cocos/Unity | MEDIUM | 逻辑层抽象 + 状态机 + 数据驱动 |
| AI 可完成 Python→C++ 转译 | MEDIUM | 需要建立转译规范 + 测试门禁 |

## 三、各层引擎适配策略

### 3.1 L1 → L2：React → Cocos Creator

```
React (Web) ──迁移──→ Cocos Creator
  ├─ 玩法逻辑 → TypeScript (Cocos 原生语言)
  ├─ UI 组件 → 重构 (Canvas/Widget 适配)
  ├─ 数据结构 → JSON Schema (中立，直接复用)
  ├─ 状态机 → 复用 (引擎无关核心)
  └─ 资源 → glTF/PNG 中立格式 (转换管线处理)
```

**迁移要点**：
- React 的逻辑代码尽量**不直接绑定 DOM**，用纯 TS 核心库
- 状态管理用引擎无关的 store（类似 Zustand 模式，但纯逻辑）
- 玩法数值/关卡数据全部 JSON 化，不硬编码
- UI 需要重构，但数据模型直接复用

### 3.2 L2 → L3：Cocos → Unity (团结引擎)

```
Cocos Creator ──迁移──→ Unity (团结引擎)
  ├─ TS 逻辑 → C# 或 C++ (通过代码生成/AI转译)
  ├─ 资源 → Unity 兼容格式 (转换器自动处理)
  ├─ 场景 → 重建 (Unity 场景图差异大)
  ├─ 程序化生成 → 复用 (引擎无关中间件)
  └─ 玩法核心 → 经 C ABI 桥接 (通用中间层)
```

**迁移要点**：
- 采用 **C++ 核心 + C ABI** 作为 L3 的主架构
- 程序化生成逻辑完全引擎无关（中间件层），各引擎只是"渲染器"
- 资产经转换管线批量处理，不手动搬运
- 使用 **IL2CPP** 或 **Native Plugin** 承载 C++ 核心

### 3.3 L3 → L4：Unity → Unreal Engine

```
Unity (团结引擎) ──迁移──→ Unreal Engine
  ├─ C++ 核心 → 直接复用 (UE 原生支持 C++)
  ├─ C ABI 层 → 天然兼容 (C ABI 是 C++ 子集)
  ├─ 程序化生成 → 复用 (引擎无关中间件)
  ├─ 资产 → FBX/glTF 导入 (UE 原生支持)
  └─ 玩法逻辑 → C++ 核心直接编译入 UE
```

**迁移要点**：
- **C++ 选型的核心收益在此体现**：UE 原生 C++，迁移成本最低
- C ABI 中间层可让 Python/TS/JS 直接调用 C++ 核心（FFI）
- 程序化生成中间件独立编译，直接集成
- 资产复用率高（glTF 是 UE 原生支持格式）

## 四、跨引擎中间件设计详解

### 4.1 中立资产格式（Neutral Asset Format）

**原则**：所有资产以**引擎中立格式**存储，各引擎只保存转换后的「渲染副本」。

| 资产类型 | 中立格式 | 转换工具 | 转换方向 |
|---------|---------|---------|---------|
| 3D 模型 | glTF (.glb) | gltf-transform | → FBX → Cocos/Unity/UE |
| 2D 贴图 | PNG/WebP (无损) | 批量处理器 | → 各引擎专用格式 |
| 音频 | WAV (源) + OGG (压缩) | 音频转换器 | → Cocos/Unity/UE |
| 动画 | FBX 动画曲线 | 动画转换器 | → 各引擎专用格式 |
| 场景布局 | JSON (Scene Schema) | 场景重建器 | → 各引擎场景格式 |
| 关卡数据 | JSON (Level Schema) | 关卡生成器 | → 各引擎数据格式 |

**目录结构**：
```
assets/
├── source/           # ★ 中立源资产（唯一真相）
│   ├── models/       # .glb 模型
│   ├── textures/     # .png 源贴图
│   ├── audio/        # .wav 源音频
│   ├── animations/   # .fbx 动画
│   ├── levels/       # .json 关卡数据
│   └── metadata/     # 资产元数据 (tags, author, version)
├── generated/        # 程序化生成产物（引擎无关）
│   ├── terrain/      # 程序化地形
│   ├── buildings/    # 程序化建筑
│   ├── items/        # 程序化物品
│   └── textures/     # 程序化贴图
└── engine/           # ★ 各引擎渲染副本（派生）
    ├── cocos/        # Cocos Creator 资源
    ├── unity/        # Unity 资源
    └── unreal/       # UE 资源
```

### 4.2 程序化生成引擎

**核心设计**：程序化生成代码**不依赖任何引擎 API**，只依赖数据 + 算法。

```
┌─────────────────────────────────────────────┐
│        Procedural Generation Core            │
│                                             │
│  ┌─────────────┐  ┌──────────────────┐      │
│  │ 种子系统    │  │ 规则引擎         │      │
│  │ (seed)      │  │ (rule-based)     │      │
│  └──────┬──────┘  └───────┬──────────┘      │
│         │                 │                  │
│  ┌──────▼─────────────────▼──────────┐      │
│  │      生成器注册表 (Generator Registry) │      │
│  │  - TerrainGen  地形生成器           │      │
│  │  - LevelGen    关卡生成器           │      │
│  │  - PropGen     装饰物生成器         │      │
│  │  - NarrativeGen 叙事生成器          │      │
│  └──────┬─────────────────┬──────────┘      │
│         │                 │                  │
│  ┌──────▼──────┐  ┌───────▼──────────┐      │
│  │ 数据输出    │  │ 资产导出          │      │
│  │ (JSON)      │  │ (glTF/PNG等中立格式)│      │
│  └─────────────┘  └──────────────────┘      │
└─────────────────────────────────────────────┘
        │                │
        ▼                ▼
  各引擎加载 JSON    各引擎导入中立资产
  (渲染为场景)       (转换渲染副本)
```

**技术实现**：
- 语言选择：**C++**（性能和跨平台最佳）+ 可选 Python 包装器（AI/脚本快速原型）
- 输出格式：JSON 数据 + 中立资产文件（glTF/PNG）
- 确定性：同一种子 → 相同输出（可复现/可调试/可共享）
- AI 协作：通过 C ABI 暴露接口，AI 可自动生成新生成器

### 4.3 玩法逻辑层（引擎无关核心）

**原则**：核心玩法逻辑用**纯 C++** 实现，通过 C ABI 暴露接口，各引擎通过 FFI 调用。

```
┌──────────────────────────────────────────────────┐
│              Gameplay Core (C++)                 │
│                                                  │
│  ┌──────────┐  ┌──────────┐  ┌──────────────┐   │
│  │ 状态机    │  │ 事件总线  │  │ 数据模型     │   │
│  │ StateMgr │  │ EventBus │  │ DataModel    │   │
│  └────┬─────┘  └────┬─────┘  └──────┬───────┘   │
│       │             │              │            │
│  ┌────▼─────────────▼──────────────▼───────┐    │
│  │         C ABI 接口层 (extern "C")         │    │
│  │  int gameplay_init();                    │    │
│  │  int gameplay_update(float dt);          │    │
│  │  void gameplay_set_state(int state);     │    │
│  │  void gameplay_emit_event(int type);     │    │
│  └──────────────────────────────────────────┘    │
└──────────────────────────────────────────────────┘
        │            │            │            │
        ▼            ▼            ▼            ▼
   ┌────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐
   │ WASM   │  │ Cocos FFI│  │ Unity PInvoke│  │ UE Plugin│
   │ (Web)  │  │ (TS)     │  │ (C#)     │  │ (C++)    │
   └────────┘  └──────────┘  └──────────┘  └──────────┘
```

**C ABI 的核心价值**：
1. **跨语言 FFI**：Python/TS/JS/C#/C++ 都能直接调用 C 接口
2. **引擎无关**：Cocos/Unity/UE 都能通过插件/桥接加载 C 动态库
3. **AI 友好**：C 头文件 + ABI 稳定，AI 可以自动生成各语言包装器
4. **Web 兼容**：可通过 Emscripten 编译为 WASM 在浏览器运行
5. **UE 原生**：UE 本身就是 C++，直接源码集成无需桥接

### 4.4 迁移工具链

**核心能力**：代码/资产/数据的跨引擎转换 + 一致性校验。

```
┌───────────────────────────────────────────────┐
│           Migration Toolchain                  │
│                                               │
│  ┌──────────────┐  ┌──────────────────────┐   │
│  │ 资产转换器    │  │ 代码转换器           │   │
│  │ AssetConv    │  │ CodeGen             │   │
│  │  - glTF→FBX  │  │  - TS→C++           │   │
│  │  - PNG→各引擎│  │  - C++→C# Wrapper   │   │
│  │  - JSON→场景 │  │  - C ABI→各语言FFI  │   │
│  └──────┬───────┘  └───────┬────────────┘   │
│         │                  │                 │
│  ┌──────▼──────────────────▼─────────────┐   │
│  │ 一致性校验器 (Consistency Verifier)     │   │
│  │  - hash 比对 (同源校验)                 │   │
│  │  - schema 校验 (数据结构)               │   │
│  │  - 功能回归 (行为等价)                  │   │
│  └────────────────────────────────────────┘   │
└───────────────────────────────────────────────┘
```

## 五、技术栈选型

### 5.1 核心中间件语言：C++17 + C ABI

**选型理由**：
| 维度 | C++ + C ABI | 备选方案 |
|------|------------|---------|
| UE 原生支持 | ✅ 完美 | Python ❌ |
| Unity 支持 | ✅ Native Plugin / IL2CPP | TS ❌ |
| Cocos 支持 | ✅ 原生插件 | Python ❌ |
| Web 支持 | ✅ WASM (Emscripten) | C# 有限 |
| Python 协作 | ✅ C ABI FFI | — |
| AI 代码生成 | ✅ 生态丰富 | — |
| 性能 | ✅ 最优 | — |

### 5.2 各层技术栈

| 层 | 引擎 | 主语言 | 中间件接口 | AI 协作方式 |
|----|------|--------|-----------|-----------|
| L1 | React | TypeScript | WASM (Emscripten 编译 C++→WASM) | AI 生成 TS 逻辑 |
| L2 | Cocos | TypeScript | C ABI FFI (通过 cocos native plugin) | AI 生成 TS + Python 原型 |
| L3 | Unity | C# + C++ | C ABI (PInvoke) + Native Plugin | Python→C++ AI 转译 |
| L4 | Unreal | C++ | 源码集成 (直接编译) | AI 生成 C++ 代码 |

## 六、AI 协作方案

## 八、风险清单

| # | 风险 | 等级 | 规避方案 |
|---|------|------|---------|
| 1 | C++ 开发成本高 | MEDIUM | AI 辅助代码生成 + Python 原型先行 |
| 2 | Unity 原生 C++ 集成复杂 | HIGH | 使用 Unity Native Plugin + IL2CPP，限制 C++ 范围 |
| 3 | 程序化生成质量不稳定 | MEDIUM | 种子可复现 + 规则引擎可调参 |
| 4 | 跨引擎行为不一致 | HIGH | 一致性校验器 + 跨引擎回归测试 |
| 5 | React→Cocos UI 无法自动迁移 | MEDIUM | UI 作为最底层优先级，人工重建 |
| 6 | 多引擎维护成本 | MEDIUM | 中间件统一入口，引擎只做渲染层 |
| 7 | Python→C++ AI 转译质量 | HIGH | 测试门禁 + 人工审查 + 迭代优化 |

# 游戏生态角色体系调研

> 目标：把"岗位（Job）"升级为"生态角色（Ecosystem Role）"。
> 一个游戏从立项到发布，不止有"研发岗"，还活在由**协作支持者、玩家、渠道平台、宣发媒体、广告方、外包劳动力**共同构成的市场生态里。
> 只有当这些角色都被建模并能互相博弈，我们才能在**游戏发布之前**对"这个市场会产生什么效果"做预演，找到**契合各方的最优生态位**——而不仅仅是让单一岗位做到局部最好。

---

## 一、从"岗位"到"生态角色"的跃迁

| 维度 | v0.1 岗位体系（已有） | v0.2+ 生态角色体系（本次扩展） |
|------|----------------------|------------------------------|
| 关注范围 | 游戏研发内部的六大板块 | 研发 + 协作支持 + 玩家 + 市场渠道 + 外部劳动力 |
| 产出逻辑 | 交付"设计/代码/美术资源" | 交付"研发产物 + 沟通 + 进度 + 市场反馈 + 生态位" |
| 决策依据 | 单点岗位职责最优 | **全局纳什均衡**：各方在给定他人策略下不再单方面改动的稳定态 |
| 时间维度 | 立项→上线 | 上线前即可做**市场预演**，模拟发布后的市场效果 |
| 角色性质 | 都是"生产者" | 有生产者、有服务者、有**消费者/玩家**、有**渠道/平台/广告** |

> 一句话概括：**当生态足够完善，我们可以在"发布"这一动作发生前，就把整个市场的"化学反应"先跑一遍。**

**圈层说明：**

1. **研发核心圈** —— 已有 v0.1 的六大板块岗位（策划/程序/美术/测试/项目/运营），是"生产"主力。
2. **协作支持圈（本次新增核心）** —— 负责让生产"跑得顺"：沟通传递、催进度、整理资产、调解求助、零工外包负载均衡。
3. **玩家圈（本次新增核心）** —— 让生态有"需求端"：当玩家、做测试、提喜好、给出付费意愿。
4. **外部市场圈（本次新增）** —— 让生态有"变现与分发端"：宣发平台、第三方小游戏平台、广告方、渠道、KOL、竞品。

## 三、协作支持圈：让"生产"跑得顺的角色

研发不是只靠"生产者"就能推进的，还需要一批"服务者"。它们不直接产出版本内容，却决定了**协作是否高效**。这正好呼应"每个岗位一个 Agent 之外，还要有协作协助的角色"。

### 1. 通讯官（Communicator / Message Relay）
- **别名**：信使 / 消息中枢 / 沟通Agent
- **职责**：
  - 在各岗位 Agent 之间**结构化地传递消息**（转译、路由、降噪）
  - 把"策划的模糊需求"翻译成"程序能执行的技术话术"，反之把"程序的技术约束"翻译回"策划能理解的产品语言"
  - 维护沟通日志、沉淀会话上下文，防止信息丢失
- **决策点**："这条消息该给谁 / 该不该合并 / 是否需要转译再发"
- **生态价值**：消除信息孤岛，是消息总线的"语义层"。

### 2. 进度督导（Progress Pusher / 催进度）
- **别名**：赶工小喇叭 / 进度追更
- **职责**：
  - 盯着各任务 DDL，**主动催进度**、发提醒、拉站会
  - 识别"卡住/阻塞"的任务并触发升级
  - 平衡"催"的力度，避免过度打扰导致反作用
- **决策点**："某任务离 DDL 还差多久？是否已落后阈值？该催还是该等？"
- **生态价值**：把"计划"变成"被推动的执行"。

### 3. 资产管理 / 清道夫（Asset Manager / Cleaner）
- **别名**：仓管 / 资源管家 / 垃圾清理员
- **职责**：
  - 整理、打标、去重、归档所有研发资产（美术资源、配置表、文档、代码库）
  - **清理垃圾**：废弃资源、冗余文件、过期分支、无用引用
  - 维护资产索引与引用关系，防止"找不到东西 / 资源冲突"
- **决策点**："这个资源是否被引用？该归档还是该删？该合并哪两个版本？"
- **生态价值**：保持系统整洁，是"效率的地基"。

### 4. 调解员（Mediator / 求助与仲裁）
- **别名**：和事佬 / 问题解决Agent / 仲裁官
- **职责**：
  - 当岗位间**扯皮、冲突、有疑问**时，主动去问、去查、去调解
  - 收集多方诉求，找根因，提出折中方案
  - 调解不了时**升级给上级仲裁**（制作人/主策划）
- **决策点**："冲突的根因是什么？各方的诉求能否兼容？是否需要升级？"
- **生态价值**：把"卡死的争议"转化为"可推进的共识"。

### 5. 零工 / 外包池（Gig Worker Pool / Load Balancer）
- **别名**：机动队 / 临时工 / 备援劳动力
- **职责**：
  - 维护一个**可按需调度的通用劳动力池**
  - 根据各岗位的**实时负载与进度压力**，把闲余/通用能力分配给吃紧的岗位，帮忙提速
  - 承担标准化、可外包的活（批量改配置、补测试用例、刷资源引用等）
- **决策点**："谁的负载最高？这块活能不能拆出去？派给哪个零工 Agent？"
- **生态价值**：**负载均衡**，让系统像真实市场一样通过"临时调配"平滑波峰。

### 6. 门卫 / 守门人（Gatekeeper）
- **别名**：质量闸口 / 合规官
- **职责**：
  - 守住各类"闸口"：发版门禁、资产入库门禁、对外发布合规门禁
  - 检查是否满足放行标准，不满足就打回并给出原因
- **决策点**："当前产出是否达到放行标准？"
- **生态价值**：把好"进/出"的关口，保证生态质量。

## 四、玩家圈：给生态装上"需求端"

没有玩家的生态是空转的。把"玩家"建模成角色后，研发就能在发布前听到"需求端"的声音。

### 1. 泛玩家（Mass Player / 大众体验者）
- **特征**：追求轻松上手、碎片化、社交分享
- **关注点**：好不好玩、上手难度、是否上瘾适度、是否值得传播
- **生态角色价值**：代表"大盘"，决定游戏的**潜在用户规模**。

### 2. 核心玩家（Core Player）
- **特征**：深度钻研、追求成就感、愿意投入时间
- **关注点**：系统深度、数值平衡、挑战性、可研究性
- **生态角色价值**：代表"长线留存"，决定**留存与口碑**。

### 3. 付费玩家（Payer / 鲸鱼）
- **特征**：愿意为体验/进度/外观付费
- **关注点**：付费性价比、成长爽感、炫耀价值
- **生态角色价值**：代表"商业化"，决定**营收能力**（也是广告方、平台分成的依据）。

### 4. 测试玩家 / 试玩员（Playtester）
- **特征**：参与内测，反馈 bug 与手感
- **关注点**：可玩性、平衡、bug、卡点
- **生态角色价值**：连接"玩家喜好"与"QA 质量"，是**需求端对研发的实时反馈回路**。

### 5. 主播 / KOL（Streamer / Influencer）
- **特征**：面向大众直播/剪辑，能放大传播
- **关注点**：节目效果、话题性、好不好展示、是否有梗
- **生态角色价值**：决定**冷启动的传播势能**。

### 6. 云玩家 / 观望者（Lurker）
- **特征**：看别人玩、关注热度，暂不亲自玩
- **关注点**：热度、口碑、社区氛围
- **生态角色价值**：代表"潜在转化池"，是宣发触达的对象。

> 玩家圈角色的"喜好"会被抽象成**结构化偏好档案**（如：操作复杂度、付费意愿、内容口味、社交需求），供研发在模拟中评估"目标玩家是否会买单"。

## 五、外部市场圈：让生态"变现与分发"

### 1. 宣发平台（Marketing / Publishing Platform）
- **代表**：应用商店、发行商、广告投放平台、线下/线上广告渠道
- **职责（角色）**：决定**曝光量与获客成本**；对游戏提出"宣发适配"要求（素材、软文、预热节奏、买量策略）
- **决策点**："以多少预算、在什么渠道、给这款游戏多少曝光？预期 ROI 是多少？"
- **生态角色价值**：连接"产品"与"用户"的**分发放大器**。

### 2. 第三方小游戏平台（Third-party Mini-game Platform）
- **代表**：微信小游戏、抖音小游戏等宿主平台
- **职责（角色）**：提供**流量与生态位**；有自身的分成规则、审核规范、社交裂变机制
- **决策点**："是否收录这款小游戏？给多少流量扶持？分成比例多少？是否推荐位？"
- **生态角色价值**：代表**轻量、社交、裂变**的流量生态，是中小游戏的重要变现通道。

### 3. 广告方 / 广告主（Advertiser）
- **职责（角色）**：在游戏内投放广告（激励视频/插屏/品牌合作）赚取收益，或作为**流量采购方**采购游戏内的广告位
- **决策点**："这个游戏的用户画像与我的广告匹配吗？愿以多少 CPM/CPI 购买？"
- **生态角色价值**：是游戏的**另一条营收曲线**（IAA 广告变现），与内购（IAP）形成商业上的**平衡取舍**。

### 4. 渠道商 / 支付商（Channel & Payment）
- **职责**：负责下载分发、支付、实名、合规、退款
- **生态角色价值**：决定**转化漏斗与分账结构**。

### 5. 竞品（Competitors）
- **职责（角色）**：占据同一生态位的其他产品
- **生态角色价值**：让"生态位"有**竞争与替代**，是纳什均衡的重要约束。

### 6. 监管 / 合规（Regulator）
- **职责**：版号、内容审核、未成年人保护、数据合规
- **生态角色价值**：设定**硬约束**，决定哪些方案"做不了"。

## 六、市场预演与纳什均衡

### 为什么"单点最优"不是"全局最优"？
> 一个策划想"把付费深度做得越深越好"，但从玩家/监管/口碑看可能过度；一个广告方想"广告塞得越多越好"，但从玩家体验与留存看可能崩盘。
> 每个角色都在**给定别人策略**下追求自己的最优，最终的稳定态往往不是任何单点最优，而是**所有角色都不愿意再单方面改动的均衡**——这正是**纳什均衡**。

### 市场预演引擎要做什么
在"发布"前，把以下变量放进一个**可运行的模拟沙盒**：

```
输入：研发产物(玩法/数值/美术/文案/商业化设计) + 各角色策略参数
                    │
                    ▼
┌─────────────────────────────────────────────────────┐
│               市场模拟沙盒 (Market Sandbox)          │
│  1. 玩家圈投放 → 泛玩家/核心/付费/测试/主播 各给反馈   │
│  2. 平台分发 → 宣发/小游戏平台/广告方 给出曝光/分成    │
│  3. 竞品与监管 → 施加竞争与合规约束                   │
│  4. 迭代博弈 → 各角色响应调整，直到逼近纳什均衡       │
│  输出：预计DAU/留存/付费/口碑/ROI/生态位健康度        │
└─────────────────────────────────────────────────────┘
                    │
                    ▼
        生态位诊断：哪里过强/过弱？该往哪个生态位挤？
        各方再调整参数 → 重新模拟 → 收敛于更合理的均衡
```

### 核心决策原则
1. **全局视角**：以"整个生态的可持续性"为目标，而非单点 KPI。
2. **多轮博弈**：允许各角色在模拟中**互相响应**，直到不再有人愿意单方面改动（收敛）。
3. **纳什均衡作为推荐解**：当模拟收敛到均衡，把它作为"可落地的方案"，同时标注**帕累托改进空间**（是否存在让至少一方更好、无人更差的方案）。
4. **敏感性分析**：改变任一参数，观察均衡是否被打破，找到**最稳的生态位**。

## 七、生态角色化改造要点

| 圈层 | 角色 | 对"发布前预演"的贡献 |
|------|------|---------------------|
| 研发核心 | 各岗位 Agent | 提供"生产出来的产品长什么样" |
| 协作支持 | 通讯/督导/资产/调解/零工/门卫 | 决定"能不能按时、干净、顺畅地做出来" |
| 玩家圈 | 泛/核心/付费/测试/主播/云玩家 | 提供"谁会喜欢、愿不愿付、会不会传" |
| 外部市场 | 宣发/小游戏平台/广告方/渠道/竞品/监管 | 提供"能发出去吗、能赚多少、生态位挤不挤" |

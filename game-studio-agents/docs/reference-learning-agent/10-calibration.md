# 10. 校准机制 · 相似度控制与多轮迭代（Calibration）

> 借鉴不是"一次成型"，而是一个**可反复校准、可精确控制相似度**的过程。
> 本机制解决两个核心问题：
> ① **相似度可检测**——衡量"这次借鉴到底像了目标多少"；
> ② **相似度可控**——可以做到"7 成参考 / 一模一样 / 只近似代码逻辑 / 只了解避免踩坑"。

## 1. 为什么需要校准

一次参考往往不完善：素材不全、理解偏差、落地走样。如果只看一次就交付，容易出现：

- **相似度过高**：照搬过头，既有"抄袭"风险，也和自有游戏割裂。
- **相似度过低**：借了等于没借，目标价值没落地。
- **维度错位**：想要"代码逻辑像"，结果美术全盘照搬。

所以需要**相似度可度量 + 相似度可调档**，并支持**多次迭代校准**直到达到目标档位。

## 2. 相似度检测（Similarity Detection）

对借鉴产物（分析报告 / Mod）计算"与目标参考的相似度"，按**多个维度**分别打分：

| 维度 | 含义 | 检测方式 |
|------|------|----------|
| 玩法相似度 `mechanics` | 核心玩法循环像不像 | 机制清单逐项比对 |
| 数值相似度 `numeric` | 数值曲线/倍率像不像 | 数值模型曲线对比 |
| 视觉相似度 `visual` | 美术风格/UI/动效像不像 | 风格向量/视觉特征比对 |
| 代码相似度 `code` | 实现逻辑/结构像不像 | 结构/逻辑指纹比对 |
| 心智相似度 `mindset` | 玩家体验/情绪节奏像不像 | 心智模型对比 |

> 相似度输出为 `0.0 ~ 1.0` 浮点分，附**逐维度明细**，便于精确校准。
> 用法：`similarity = CalibrationEngine.measure(mod, target)` 返回 `{mechanics:0.7, numeric:0.5, ...}`。

## 3. 相似度控制档位（Similarity Presets）

用户提出的四种借鉴程度，映射为 4 个**相似度目标档位**：

| 档位 | 目标相似度 | 含义 | 适用场景 |
|------|-----------|------|----------|
| `full_clone` | ≈ 1.0 | **一模一样** | 需要完整复刻某个玩法系统（含视觉/数值/代码） |
| `high` | ~ 0.7 | **7 成参考** | 借鉴主干，保留自有特色，只像"主要结构" |
| `code_only` | 代码维高 / 其余低 | **只近似代码逻辑** | 只要实现思路像，美术/数值完全自主 |
| `anti_pattern` | 低（规避） | **只了解避免踩坑** | 反向参考：相似度应尽量低，只学失败教训 |

### 3.1 档位语义细化

```
full_clone (≈1.0)     一模一样的复刻——每个维度都追高相似度
        │
high (≈0.7)           7 成参考——主干像，细节差异化（默认推荐，平衡借鉴与创新）
        │
code_only             只像代码逻辑——code 维度高，visual/numeric 维度保持自有
        │
anti_pattern (≈0.1)   反向借鉴——相似度刻意压低，只吸收"别踩的坑"
```

### 3.2 档位控制（Calibration Control）

校准器根据**目标档位**与**当前实测相似度**的偏差，输出**调整指令**：

```yaml
calibration_target:
  preset: "high"                    # 目标档位：full_clone / high / code_only / anti_pattern
  similarity_goal:
    mechanics: 0.7                  # 玩法目标相似度
    numeric:   0.5
    visual:    0.3
    code:      0.6
    mindset:   0.4
  tolerance: 0.08                   # 允许偏差，超过则触发下一轮校准

current_similarity:                 # 当前实测（第 1 轮）
  mechanics: 0.88                   # ↑ 偏高，需降
  visual:    0.72                   # ↑ 明显偏高，需降
  code:      0.62                   # ✓ 达标

adjustment:                         # 校准器输出的调整指令
  - {dim: "visual", action: "decouple", note: "视觉相似度过高，改为自有风格，仅保留交互节奏"}
  - {dim: "mechanics", action: "trim", note: "玩法过像，裁剪其中 2 个子系统，差异化"}
```

### 3.3 档位 → 调整动作映射

| 当前相似度 vs 目标 | 调整动作 |
|--------------------|----------|
| 某个维度 **高于** 目标 | `decouple`（解耦，改为自有） / `trim`（裁剪） |
| 某个维度 **低于** 目标 | `enrich`（补足素材） / `deepen`（加深拆解） |
| 全部 **在容差内** | `stable`（达到目标，可进入落地） |

## 4. 多轮迭代校准（Iterative Calibration Loop）

用户提到"**一次参考不完善，可以多次，可以持续**"。校准是一个循环，直到相似度进入目标档位的容差带：

```
        ┌───────────────────────────────────────────────┐
        │                ITERATIVE CALIBRATION          │
        ▼                                               │
┌──────────────┐   ┌──────────────┐   ┌──────────────┐   │
│  探索/理解     │ → │  相似度检测    │ → │  目标档位判定   │   │
│  (见09模式)   │   │  measure      │   │  compare      │   │
└──────────────┘   └──────┬───────┘   └──────┬───────┘   │
                          │                  │           │
                          │            ┌─────┴─────┐     │
                          │        在容差内? 稳定     │ 否  │
                          │            └─────┬─────┘───┐
                          │                  ▼          │
                          │           到达目标 → 进入落地 │
                          │                            │
                          │     ┌──────────────────────┘
                          │     │ 生成调整指令 (adjustment)
                          ▼     ▼
                    ┌──────────────────┐
                    │  下一轮探索/修正   │ ← 按调整指令补足/解耦/裁剪
                    └──────────────────┘
```

### 4.1 迭代终止条件

| 条件 | 说明 |
|------|------|
| 达标 | 所有目标维度的相似度都在容差带内 → `stable`，进入落地 |
| 达上限 | 达到 `max_rounds`（默认 3 轮，可配置）仍未达标 → 保留最佳一轮，标记 `PARTIAL` 上报人工 |
| 收敛 | 相邻两轮相似度变化 < `converge_epsilon`（收敛阈值）→ 视为已收敛，停止空转 |

### 4.2 持续校准（Continuous）

对**已上线**的借鉴 Mod，可持续跟踪其与目标的偏差及**玩家反馈**：

- 上线后 1 周：复测相似度 + 对比玩家满意度，确认"像度是否合适"。
- 若相似度过高导致"雷同感/抄袭投诉" → 触发 `decouple` 下调相似度。
- 若相似度不足导致"没借鉴出价值" → 触发 `enrich` 补足。

## 5. 与元学习（08）的衔接

校准机制与科研探索中的**元学习**协同：

- 每次校准的"目标档位 vs 实际反馈"结果回写元知识库，学习"**不同诉求该设多高的相似度**"。
- 例如：历史上"7 成参考"的 Mod 玩家好评更高 → 元学习建议默认档位从 `full_clone` 下调到 `high`。
- 校准偏差大时，多 Agent 博弈可介入评审"该不该降/升相似度"。

## 6. 代码落点

- 配置：`config/agent_boost/calibration_preset.yaml`（4 个相似度档位 + 各维度目标值 + 容差）
- 代码：`agent_behavior.py` 中的 `CalibrationEngine` 类（`measure()` 相似度检测 / `calibrate()` 档位控制 / `iterate()` 多轮迭代）
- 岗位：`roles.yaml` 中 `reference_learner.agent_logic.calibration`（相似度控制决策点）

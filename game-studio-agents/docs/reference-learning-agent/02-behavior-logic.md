# 02. 行为逻辑（Behavior Logic）

Agent 遵循"**收到借鉴任务 → 理解 → 评估 → 决策 → 落地 → 验证 → 归档**"的闭环行为逻辑。核心是"**先判断值不值得做，再决定怎么做，最后做成模组交付**"。

## 1. 行为状态机

```
        ┌──────────────────────────────────────────────────────┐
        │                    IDLE（空闲监听）                    │
        └───────────▲───────────────────────────────┬──────────┘
                    │                               │ 触发（见 03）
          ┌─────────┴─────────┐                     │
          │   INPUT_PENDING   │                     │
          │ 收集并归一化素材   │◄────────────────────┤
          └─────────┬─────────┘                     │
                    ▼                               │
          ┌──────────────────┐  不满足(砍掉/放弃)    │
          │   ANALYSIS        │─────────────────────┤
          │ 理解+拆解+还原    │                     │
          └─────────┬─────────┘                     │
                    ▼ 产出《机制分析报告》            │
          ┌──────────────────┐  评分低→建议不落地     │
          │   ASSESS          │─────────────────────┤
          │ 适配度评估+取舍   │                     │
          └─────────┬─────────┘                     │
                    ▼ 通过                        │
          ┌──────────────────┐                     │
          │   DECIDE          │                     │
          │ 生成借鉴决策单    │                     │
          └─────────┬─────────┘                     │
                    ▼                               │
          ┌──────────────────┐                     │
          │   BUILD_MOD       │ 落地层：视觉/展现/功能 │
          │ 生成+打包 Mod     │                     │
          └─────────┬─────────┘                     │
                    ▼                               │
          ┌──────────────────┐  校验失败→打回 BUILD  │
          │   SANDBOX_VERIFY  │                     │
          │ 沙盒验证+开关/回滚 │                     │
          └─────────┬─────────┘                     │
                    ▼ 通过                        │
          ┌──────────────────┐                     │
          │   REVIEW_COMMIT   │ 人工/自动审核后合入    │
          │ 归档+写知识库     │                     │
          └─────────┬─────────┘                     │
                    ▼                               │
                  IDLE（回到监听）─────────────────────┘
```

## 2. 关键行为规则

### 规则 A：先分析后动手（不跳过 ASSESS）
- 任何借鉴都必须先产出《机制分析报告》和《契合度评分卡》。
- 契合度低于阈值（默认 60 分）→ 直接给出"建议不落地"结论，不进入落地层。

### 规则 B：模组化落地（不直接改主游戏）
- 所有落地改动必须封装为 Mod，禁止越过 Mod 层直接修改主游戏基线。
- 每个 Mod 独立开关、独立回滚，保证"借鉴可逆、可回收"。

### 规则 C：增量借鉴（一次只改一个点）
- 单个触发周期只聚焦一个"借鉴点"，避免大改造成失控。
- 多借鉴点排队执行，优先级由【契合度 × 收益 × 成本】排序。

### 规则 D：人机共治（按成熟度分层审核）
- L1/L2 能力产出需人工审核后才合入主分支；L3 才允许自治合入。
- 高风险改动（涉及核心数值/经济循环）强制人工确认。

### 规则 E：记忆与复用（知识库回写）
- 每次借鉴的《分析报告》《决策单》《Mod》归档到仓库知识库。
- 后续相似借鉴优先检索已有知识，避免重复劳动、保持风格一致。

## 3. 决策单（Decision Slip）产出格式

每次借鉴结束后，Agent 必须产出结构化"决策单"，作为沟通与审计的载体：

```yaml
reference_decision:
  source_game: <目标游戏名>
  borrowed_mechanism: <借鉴的机制>
  mechanism_analysis:   # 理解层
    core_loop: <核心循环描述>
    systems: <涉及系统>
    numeric_model: <数值模型摘要>
  assessment:           # 迁移层
    fit_score: <0-100>
    keep: [<整体搬的要素>]
    trim: [<需裁剪的要素>]
    adapt: [<需改造的要素>]
    drop: [<放弃的要素>]
    innovation: <差异化创新点>
    risk: <合规/风险结论>
  mod:                  # 落地层
    mod_id: <唯一ID>
    scope: [visual|presentation|feature]
    files: [<改动文件清单>]
    enabled_by_default: <bool>
    rollback_point: <回滚快照>
  review:               # 审核
    level: <L0-L3>
    status: <pending|approved|rejected>
```

## 4. 行为约束（禁止项）

- ❌ 不得在未产出分析报告前直接改主游戏。
- ❌ 不得整体复制受版权/专利保护的美术、代码、玩法实现（仅做"机制借鉴"）。
- ❌ 不得在沙盒验证通过前将 Mod 标记为"可上线"。
- ❌ 不得越过知识库直接重复做已被评估为"放弃"的借鉴。

# 09. 校验机制 · 探索多模式（Exploration Modes）

> 借鉴不等于"一股脑把目标游戏的所有信息都抓回来"。不同目标、不同阶段需要**不同的探索模式**。
> 本机制回答三个问题：**从多少个渠道获取信息？包含哪些信息类型（美术/视频/动效/代码逻辑…）？探索到什么深度？**
> 由 `reference_learner` 在进入分析前先做一次"**探索模式决策（Exploration Decision）**"，作为校验机制的入口。

## 1. 为什么要"多模式"探索

同一个《X》游戏，三种诉求完全不同：

| 诉求 | 需要看什么 | 若一律"全量深挖" |
|------|-----------|------------------|
| 借鉴它的**美术风格** | 截图、原画、UI 展示 | 浪费：拉到代码逻辑反而干扰 |
| 借鉴它的**战斗代码逻辑** | 源码、数值公式、事件循环 | 浪费：看美术视频几乎无帮助 |
| 全面复刻一个**玩法系统** | 视频+动效+数值+代码全都要 | 单一渠道会漏关键细节 |

结论：**探索模式必须可配置、可组合**，而不是一刀切全量抓取。

## 2. 探索模式的三维定义

每一个探索模式由三个维度刻画，构成一个可组合的"探索档位"：

```
探索模式 = 渠道广度(Channel Breadth)
         × 信息类型(Info Types)
         × 探索深度(Exploration Depth)
```

### 2.1 维度一：渠道广度（Channel Breadth）—— 从多少个渠道获取

| 档位 | 取值 | 说明 | 典型渠道 |
|------|------|------|----------|
| `single` | 1 | 单渠道 | 只用一个来源（如官方宣传片） |
| `multi` | 2-4 | 多渠道交叉 | 官方 + 实机 + 社区 + 设计文档 |
| `all` | ≥5 | 全渠道核验 | 官方 + 实机 + 图文 + 代码 + 玩家反馈 + 竞品对比 |

### 2.2 维度二：信息类型（Info Types）—— 包含哪些维度

借鉴的"素材"不是同质化的，需要按类型显式声明是否纳入：

| 信息类型 | 代码标识 | 说明 | 主要载体 |
|----------|---------|------|----------|
| 美术 | `art` | 视觉风格、UI、配色、图标 | 截图/原画/UI展示 |
| 视频 | `video` | 玩法表现、镜头语言、节奏 | 宣传片/实机/录屏 |
| 动效 | `motion` | 反馈动效、转场、粒子 | 录屏/演示/GIF |
| 数值 | `numeric` | 数值曲线、经济循环、成长节奏 | 设计文档/拆解贴 |
| 代码逻辑 | `code` | 玩法逻辑、事件循环、系统耦合 | 源码/开源仓库 |
| 玩家心智 | `mindset` | 玩家动机、情绪曲线、心流 | 社区讨论/评测/问卷 |
| 合规 | `compliance` | 版权/专利/商标风险 | 专利库/法务评审 |

> 任一类型未纳入时，探索阶段**不采集**该维度，分析报告也不产出对应章节（避免无效投入）。

### 2.3 维度三：探索深度（Exploration Depth）—— 探索到什么程度

| 档位 | 取值 | 含义 |
|------|------|------|
| `glance` | 浅 | 只做整体认知：它是什么、核心卖点、一眼印象 |
| `dig` | 中 | 深入拆解某个子系统：结构、循环、实现方式 |
| `full` | 深 | 全维度还原：机制+数值+视觉+代码，可供直接迁移 |

## 3. 内置探索模式（预设档位）

为方便调用，内置 6 个常用档位（在 `config/agent_boost/exploration_preset.yaml` 中可扩展）：

| 预设名 | 渠道广度 | 信息类型 | 深度 | 典型用途 |
|--------|---------|---------|------|----------|
| `art_style` | `multi` | `art` | `glance` | 借鉴美术风格 |
| `gameplay_loop` | `multi` | `video,motion,numeric,mindset` | `dig` | 借鉴核心玩法循环 |
| `code_logic` | `single`+`multi` | `code,numeric` | `full` | 借鉴代码逻辑（无美术干扰） |
| `full_clone` | `all` | `art,video,motion,numeric,code,mindset` | `full` | 全维度复刻一个玩法系统 |
| `competitive_bench` | `all` | `numeric,mindset,compliance` | `dig` | 竞品对标（只求客观数据） |
| `anti_pattern` | `all` | `video,mindset,numeric,compliance` | `dig` | 反向借鉴：避开它的失败点 |

## 4. 探索模式决策流程（进入分析前的校验）

```
触发任务
   │
   ▼
┌──────────────────────────┐
│  探索模式决策             │  ① 明确诉求：要"美术/玩法/代码/避开"哪一类？
│  EXPLORATION DECISION    │  ② 选渠道广度：single / multi / all
│                          │  ③ 选信息类型：哪些维度纳入？
│                          │  ④ 选深度：glance / dig / full
└───────────┬──────────────┘
            ▼
  输出《探索计划 ExplorationPlan》
            │  含：模式档位、渠道清单、信息类型、深度、预算(时长/调用)
            ▼
┌──────────────────────────┐
│  探索执行 EXPLORE         │  按计划采集，只采集声明纳入的渠道与类型
│  (多轮迭代, 见 10 校准)   │
└───────────┬──────────────┘
            ▼
  产物：仅含"该模式维度"的素材包 → 进入 L1 理解层
```

### 4.1 探索计划（ExplorationPlan）数据结构

```yaml
exploration_plan:
  request: "参考《X》的美术风格"
  mode_preset: "art_style"          # 或自定义
  channel_breadth: "multi"          # single / multi / all
  info_types: ["art"]               # 只采集美术
  depth: "glance"
  budget:
    max_channels: 3                 # 渠道数量上限
    max_duration: 20min             # 探索时长上限
    max_tool_calls: 12              # 工具调用预算
  anti_targets: []                  # 明确"不要参考"的点（见反参考模式）
```

### 4.2 反参考模式（Anti-Pattern）

用户提到"**还是了解他的情况，避免他这样**"——这就是**反参考（Negative Reference）**模式：
借鉴目的不是"学它"，而是"**搞清楚它哪里做得差，避免踩同样的坑**"。

- 进入方式：模式预设 `anti_pattern`，或 `request` 中带 `avoid:` 意图。
- 探索重心：视频/动效的**失败表现**、数值的**失衡点**、玩家心智的**流失点**、合规的**踩雷点**。
- 产出：`anti_report`（失败清单 + 规避策略），而非可迁移的 Mod。
- 合规：反参考**只产出负面清单**，不复制任何受保护内容。

## 5. 模式约束与默认值

- **默认模式**：`gameplay_loop`（多渠道 + 玩法相关类型 + 中等深度）——最通用的安全起点。
- **约束**：信息类型必须显式声明；未声明的维度探索阶段**不采集**。
- **预算保护**：每个模式都带 `budget`，防止"探索过度"（无限制抓取=资源浪费+信息过载）。
- **可组合**：`channel_breadth / info_types / depth` 三者自由组合，形成自定义档位，不限于内置 6 个。

## 6. 代码落点

- 配置：`config/agent_boost/exploration_preset.yaml`（6 个预设档位 + 三维定义）
- 代码：`agent_behavior.py` 中的 `ExplorationPlanner` 类（`plan()` 决策探索模式）
- 岗位：`roles.yaml` 中 `reference_learner.agent_logic.exploration`（探索模式决策点）

# 11. 强化能力使用标注（Boost Capability Usage）

> **本文档是强化能力（Capability Boost）的"使用说明书 / 标注清单"。**
> 强化能力是一组**功能独立、可单独启用/关闭**的增强技术（思维模式路由 / 科研探索 / 多 Agent 博弈），
> 因其功能不同于"游戏借鉴管线"本体，已拆分为**单独 Issue** 跟踪，不在"借鉴管线"Issue 内混排。
> 使用本 Agent 前，请先阅读本标注。

## 1. 强化能力总览（谁可以用）

| # | 能力 | 一句话 | 是否可选 | 默认状态 |
|---|------|--------|:--------:|:--------:|
| B1 | 思维模式路由（Routing） | 按任务自动切换到 spec/react/weak 三波段思维，推高上限 | 可选 | 启用 |
| B2 | 科研探索（元学习/树探索/假设求证） | 让借鉴像"研究者求证、棋手推演" | 可选 | 启用 |
| B3 | 多 Agent 博弈评审（Debate） | 不同思维链 Agent 辩论，仲裁出更稳决策 | 可选 | 启用 |

> 三者**互相独立**，可单独关停；全部关闭即退化为"未强化"的普通 `reference_learner`，不影响主流程。

## 2. 怎么用（启用 / 关闭 / 回滚）

所有强化能力都以"**可插拔 Mod**"方式挂载（借鉴 dsh-super-injector），通过配置开关控制：

```yaml
# roles.yaml → reference_learner.boost
boost:
  routing:               # B1 思维模式路由
    enabled: true        # ← 关闭则：所有任务不再自动切思维模式
  scientific_exploration: # B2 科研探索
    enabled: true        # ← 关闭则：不做元学习/树探索/假设求证
  multi_agent_debate:    # B3 多 Agent 博弈
    enabled: true        # ← 关闭则：借鉴决策不做多视角辩论
  boost_mods:            # 可插拔强化 Mod 清单
    - {name: "routing-standard", injectable: true, rollback: true}
    - {name: "methodology-skills", injectable: true, rollback: true}
```

- **启用**：`enabled: true`（或注入对应 Mod）。
- **关闭**：`enabled: false`（即刻停用，主流程不受影响）。
- **回滚**：`rollback: true` 表示可在运行时一键回退到未强化状态。

## 3. 每个能力的"何时用 / 用在哪"

### B1 思维模式路由 —— 用在哪

| 阶段 | 路由到 | 备注 |
|------|--------|------|
| L1 理解（读/分析） | `spec` | 计划-集体、读优先 |
| L2 迁移（评估/取舍） | `spec` 或 `weak` | 读优先或分类 |
| L3 落地（写 Mod） | `react` | 执行者、免仪式 |
| 复合/模糊任务 | `weak` | 模型自分类 |

**不用它的时候**：任务模式单一、无需切换；或用户已显式指定固定思路时。

### B2 科研探索 —— 用在哪

- **元学习**：每次借鉴结束复盘，迭代"契合度评估标准"。
- **树探索**：一个借鉴点有多个落地方案时，并行推演并剪枝。
- **假设求证**：对"这个机制是否适合我们"先假设后求证。

**不用它的时候**：简单借鉴、时间敏感、只需快速照搬时（会拖慢节奏）。

### B3 多 Agent 博弈 —— 用在哪

- **高风险/大决策**（全维度复刻、大改动 Mod）：让辩手/评审/怀疑者辩论。
- **有分歧** 的借鉴决策：用仲裁加权收敛。

**不用它的时候**：低风险小改动，直接走单 Agent 流程更快。

## 4. 能力分级（信任度标注）

每个强化能力有**成熟度分级**，决定"自动执行还是人工确认"：

| 分级 | 含义 | 强化能力适用 |
|------|------|--------------|
| L0 | 不具备（人工完成） | 初期可全部 L0 |
| L1 | 可辅助（产草稿，人工确认） | **默认**：路由/科研/博弈都先出建议，人工确认 |
| L2 | 可执行（自动生成+自动校验，人工审核后合入） | 信任度高后升级 |
| L3 | 可自治（自动合入，仅告警） | 长期稳定后才开放 |

> 默认 `maturity: L1`，所有强化能力输出均需人工确认后再落地。

## 5. 使用前提与风险标注

| 关注点 | 说明 |
|--------|------|
| **不换模型** | 强化靠提示词/插件/路由，不依赖更换底层模型 |
| **路由刚需** | 正确路由=模型上限放大器；错误路由会拉低效果（论文实测 91/6 vs 99/96） |
| **隔离** | 多 Agent 博弈各角色上下文隔离，避免相互污染 |
| **回滚兜底** | 所有强化能力可一键回滚，不影响主流程 |
| **成本** | 博弈/科研会多消耗调用；简单任务慎用（有预算保护） |
